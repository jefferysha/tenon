## 二、发现清单

**M1（medium，相悖）**：规格要求环境变量 `TENON_INIT_IN_PLACE=1` 触发的原地初始化也输出原因，实现没有输出。
- 规格：`task-worktree-isolation` R1（「以下情况 SHALL 原地初始化并输出原因 … 调用方显式传入 `--in-place` 或环境变量 `TENON_INIT_IN_PLACE=1`」）。
- 实现：`init-worktree.ts` 行 51，`plan.reason !== 'requested' || inPlaceFlag` 才打印，环境变量触发时静默。
- 测试：`init.test.ts` 行 592 断言「不输出原因」。
- 实现的理由是环境变量属测试工装约定。design.md 行 62 只写「测试工装用环境变量」，没有说静默。请主线裁决：改规格措辞，或让实现输出原因。

**M2（medium，规格漏写）**：`start_sha` 作为候选，实现还多要求「提交者时间不晚于 `created_at` + 60 秒」，delta spec 只写了「是 HEAD 的祖先时」。
- 规格：`change-start-point` R1。
- 实现：`change-start.ts` 的 `recordedStartIsPlausible`，以及 `startFromCandidates` 的入选条件。
- 该条件在 design.md 行 88、技术设计 `setup-host-agents-step-progress-design.md` 行 113 和 `docs/CONTRACT.md` 行 698–702 都有记载，只缺 delta spec。该条件只会让起点前移、范围变宽，不会漏算，所以不是 `high`。建议补进 delta spec，让规格与实现一致。

**L1（low）**：「失败的流转不打印」依赖宿主 PostToolUse 只在命令成功时触发。hook 自己拿不到退出码（`step-progress.sh` 头部有说明），没有自动化测试验证这一点，只能真机确认。属 tasks.md 第一条真机验收的范围。

**L2（low，多做但与规格同向）**：`stop` 动作 `code: finished` 也带 `cleanup`（`statusStepFinish.ts` 的 `finishedStop`），规格只写了 `finish-change`。`SKILL.md` 已同步说明，建议规格补一句。

**L3（low，支撑性改动，规格未逐条提及）**：
- `legacy-import.ts` 保护 `start_sha`。
- `agentSkillGate.ts` 复用 `agentOwnedSkills`。
- `check.ts`、`check-skills.ts` 传递 `event`。
- `test-trust.ts` 展示 `setup`。
- `.github/workflows/ci.yml` 与 `tools/*` 的 `--in-place` 或 `TENON_INIT_IN_PLACE`。

这些都是实现上述 Requirement 所必需，或属于测试工装，不按多做处理。
