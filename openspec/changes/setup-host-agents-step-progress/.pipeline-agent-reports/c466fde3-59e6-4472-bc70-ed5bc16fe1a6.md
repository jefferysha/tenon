# builder 报告：`start_sha` 改为伴随文件承载（N-1 兼容修复）

## 起因

`tenon test run --suite bundle` 的 N-1 兼容门 13 项失败：Task 8 把 `start_sha` 写进 canonical wire 的 `state.fields`，
上一正式版 v0.3.1 校验字段闭集，读到带它的任务一律报 `canonical state.fields 不是 FIELD_ORDER 闭集`。`start_sha` 每个新任务都会写，
违反 `tools/lib/n-minus-one-compat.sh` 的合同（当前版本隐式写下的数据 N-1 必须读得了）。

## 改动

- `packages/kernel/src/state/start-sha-store.ts`（新）：按 revision + revisionId 命名、绑定该 revision `stateDigest` 的不可变伴随记录
  `.pipeline-run/start-sha/<rev6>-<revisionId>.json`，与 `review-acknowledged-via-store.ts` 同一套机制；非空才发布，先于 revision / current 指针；
  没有记录读作空串；篡改、绑定不符、形状非法、符号链接一律失败关闭；开发版 wire 里带着 `start_sha` 时沿用 wire 值，下一次写入改发伴随记录。
- `review-gate-fields.ts`：`start_sha` 进 `COMPANION_BACKED_FIELDS`；`revision-companions.ts`：异步与同步两条还原路径、发布路径都接上。
- `run-revision-codec.ts`：wire 构造按 `COMPANION_BACKED_FIELDS` 统一剔除；`state-projection-codec.ts`：开发版 YAML 投影（多一行 `start_sha:`）判为当前 / 过期而不是漂移；
  `legacy-import.ts`：`start_sha` 列为受保护字段。
- 逻辑行为不变：`tenon get <c> start_sha`、`changeStartOfFields`、起点解析、`set` / `set-many` / `cas` 拒写。
- `tools/oracle/run.sh` 删掉 Task 8 为 wire 上的 `start_sha` 加的 YAML 白名单；`docs/CONTRACT.md`、`docs/usage/default-workflow.md`（中英）、`CONTEXT.md`、
  `docs/TEST-REALITY.md` 改为：伴随文件承载、N-1 可读、N-1 续写后当前版本读到空值并退回上游候选。
- 新测试 `packages/kernel/src/state/start-sha-store.test.ts`（18 例）；`store.test.ts`、`run-revision-store.test.ts`、`change-start-point.integration.test.ts`、
  `init.test.ts`、server `server.test.ts`、triage `workflow-run-create-repository.test.ts` 的断言改为伴随形式。
- 重建 `packages/cli/dist/tenon.mjs`、`packages/server/dist/dashboard.mjs`。

## 证据

- RED：18 个新测试先因功能缺失失败（wire 里仍有 `start_sha`、没有 `start-sha/` 目录）；手工 N-1 实证：修复前 v0.3.1 `status --json` 报闭集错误、exit 1。
- GREEN：修复后 v0.3.1 读当前版本新建的任务 exit 0，并能续写；当前版本读回续写后的任务，`start_sha` 为空、其余字段正确。
- 主线用 `tenon test run --suite bundle` 复跑（本机开发安装已同步到修复后的源码）：87 通过 / 0 失败，N-1 兼容门全过。
- builder 自测：全量 vitest 745 files / 11002 passed / 0 failed；tsc 干净；`test:hooks` 2308 passed；`npm run oracle` 0 处不一致（去掉白名单后）；
  check-architecture、repository-hygiene、check-docs、check:comments 全过。

## 遗留

- 开发版建的、wire 里带 `start_sha` 的任务，要经修复后的两次写入，v0.3.1 才读得了（它校验直接前驱 revision；不可变历史不改写），已写进 CONTRACT。
  本任务自己的状态里没有 `start_sha`（由更早的运行时建立），不受影响。
- 已登记的 proposal / design / 技术设计 / ADR / 计划仍写着「升级前运行时读不了带 `start_sha` 的任务」，现在与实现及 CONTRACT 不一致；
  这是存储方式的改进，不改需求语义，本步不改已登记文档。
- 每个 revision 多一个小伴随文件，与现有伴随字段同样的取舍。
