# backend-quality 评审报告：setup-host-agents-step-progress

## 覆盖摘要

范围是 `git status` 列出的 changed 与 untracked 文件，约 150 个，不含 dist 构建产物和 `.tenon` 测试记录。我完整读了全部新增的核心模块，并读了 `fingerprint.ts`、`host-local.ts`、`changed-files.ts`、`router.sh`、`hooks.json` 的 diff。其余大量改动文件（`i18n`、`program-*`、`transition-*`、server 路由、docs 等）只按改动面抽查，没有逐行审。我没有跑测试或 CLI，工作区没有变化。

逐能力覆盖结论：

1. **用户级子代理安装与卸载、目录解析**（`host-agent-install.ts`、`host-agent-fs.ts`）：通过。
   - 配置目录只采用绝对路径的环境变量，安装、卸载、派发判定用同一个 `hostAgentsDir`。
   - 清单读改写在锁内完成，先写文件后写清单。
   - 只有目标文件本身是符号链接才拒绝。
   - 清单条目一律经 `parseHostAgentPath` 重新拼路径，不信任清单里的键。
   - 清单损坏时已有文件不改不删。
   - 原子写用 `wx` 加唯一临时文件名，失败时清理。
2. **派发判定**（`host-subagent-resolve.ts`）：通过。
   - 只读比对，名字先经 `parseHostAgentPath` 校验，防路径逃逸。
   - 同时查当前根和主检出里的同名项目级文件（`shadowed`）。
   - `main-checkout.ts` 里 git 失败、超时都返回 `undefined` 而不抛错，超时 1.5 秒。
3. **旧项目级文件清理**（`host-agent-files.ts` 与删除 `host-agent-prune.ts`，server 侧 `hostAgentPrune.ts`）：抽查通过，与安装共用 `host-agent-fs` 的探查与原子写，没有独立发现。
4. **步骤清单 CLI 与 hook**（`workflow-progress.ts`、`step-progress.sh`、`step-progress.ts`、`hooks.json`）：通过，有一条 low 发现。
   - hook 是纯 bash，只匹配名字 `[a-z0-9][a-z0-9-]*`，不执行命令内容。
   - 用 `pipeline_json_escape` 转义后输出，任何异常都 `exit 0`。
   - CLI 失败时 stdout 为空。
5. **任务起点 start_sha**（`change-start.ts`、`start-sha-store.ts`、`changed-files.ts`）：通过。
   - 提交 id 严格校验为 40 或 64 位十六进制，`usableBase` 拒绝以 `-` 开头的值，避免被当成选项。
   - 伴随文件被改写时，用提交时间与 `created_at` 加 60 秒做校验，校验不过只会让改动范围变宽，不会漏算。
   - `gitOk` 超时抛错，不当成「不是祖先」。
   - 无关历史取空树。
6. **任务 worktree 建立、列出、查找**（`task-worktree.ts`、`task-worktree-list.ts`、`init-worktree.ts`、`router.sh`）：通过。
   - 任务名正则校验后才拼路径和分支。
   - 先查路径冲突和分支冲突，失败时回滚。
   - 排除规则只写 `.git/info/exclude`。
   - 列出时对 `/var` 和 `/private/var` 两边都做 `realpath` 后比较，防越界。
   - `router.sh` 对 worktree 路径里的换行、`<`、`>`、`;`、`=` 直接不收，防止拆开或冒充 dispatch 键值。
   - 主检出已有同名任务时拒绝建 worktree。
7. **worktree 构建版本**（`build-revision.ts`、`buildRevisionAssessor.ts`）：抽查，未发现问题。
8. **工作区指纹跳过 `.claude/worktrees/`**（`fingerprint.ts`、`host-local.ts`）：通过，有一条 low 发现。
   - 已被 git 跟踪的路径仍计入。
   - 便携版与完整版共用同一套跟踪判定，两者不会对「是否已跟踪」给出不同答案。
   - git 判定不了时两个指纹都不跳过任何东西，行为退回旧版。
9. **退回边技能门与 `--subagent none`**（`agent-owned-skills.ts`、`transition-step-gates.ts`、`agentSkillGate.ts`）：通过。
   - 冻结记录读不到、身份缺失或绑定不符时返回空集，不放宽门禁。
   - 前进边不豁免任何技能。
   - `--subagent none` 的 CLI 侧只抽查了入口，没有逐行审。

## 发现清单

- **low**：`hooks/step-progress.sh:31` 的名字正则只收小写字母、数字和连字符，而 `task-worktree.ts` 和 `isValidChangeName` 允许大写与下划线。含大写或下划线的任务名流转后不打印清单，是静默漏打。修法：对齐字符集，或在文档里写明限制。
- **low**：`packages/kernel/src/workspace/fingerprint.ts:395-398`。完整指纹现在会跳过未跟踪的 `.claude/worktrees/`。已有该目录的项目里，此前绑定的 build revision 和评审结论会在升级后变成 stale。这是文档里已说明的取舍。修法：在 CHANGELOG 或 upgrade 说明里写明这一点。
- **low**：`packages/kernel/src/infrastructure/host-agent-install.ts:236-240`。卸载时对清单做 `lstat`，非 ENOENT 的错误（例如 EACCES）被吞掉，继续进入 `withManifest`，由后者给出读不出清单的结果，行为上可接受。修法：这类错误直接上报，信息更准确。
- **low**：`packages/kernel/src/workspace/task-worktree-list.ts:86`。`inside.startsWith('..')` 会把名为 `..foo` 的合法子目录误判为越界。任务名正则不允许 `.`，所以实际不触发。修法：改成判断 `inside === '..' || inside.startsWith('..' + sep)`。
- **low**：`packages/kernel/src/workspace/task-worktree.ts:122-151`。`createTaskWorktree` 的路径与分支检查和 `git worktree add` 之间有 TOCTOU 窗口，同名并发创建时会走到普通错误并触发回滚。因为回滚按路径和分支名清理，有极小概率清掉另一个并发创建者刚建出来的同名目录。窗口很小，同一任务名并发 `init` 本身就不合理。修法：可选，建前先建占位锁。

## 残余风险

- 我没有运行测试或 CLI，行为结论都来自静读。
- `packages/cli/src/commands/*`、`program-*` 和 server 路由的改动只按改动面抽查。
- `step-progress` 依赖宿主 PostToolUse 只在命令成功时触发这一语义，hook 自己没法判断退出码。
- `uninstall` 和 `install` 的跨目录清单分组语义设计严谨，但依赖调用方始终传同一份 `hostAgentsDir`。
