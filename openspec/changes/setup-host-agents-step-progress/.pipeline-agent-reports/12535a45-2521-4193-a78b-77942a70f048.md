# 安全评审报告：setup-host-agents-step-progress

候选：`workspace:sha256:99e7fc92336351dd13e9779c27a6b790ec6155030e1bd11bac152f202ddc6ba5`。本次只读审查，未运行测试，也未改动任何文件。

## 新增入口与出口

入口：
- 环境变量 `CLAUDE_CONFIG_DIR` 和 `CODEX_HOME`。
- 用户可写文件 `<configRoot>/agents/host-owned.json`。
- 项目根的 `.pipeline-owned.json`。
- PostToolUse hook 收到的 stdin JSON，里面有命令文本和 cwd。
- 测试目录里的 `setup` 字符串。
- `start_sha` 伴随文件 `.pipeline-run/start-sha/*.json`。
- `tenon agent install|uninstall` 的参数。

出口：
- 写用户级 `agents/tenon-*.md|toml`、清单和锁目录。
- 删项目级旧 agent 文件。
- hook 调用 `tenon workflow progress <NAME>`。
- `spawn(setup, {shell:true})`。
- `git worktree add/remove`、`git branch -D`，以及追加 `.git/info/exclude`。
- `git merge-base`、`git show`。

## 逐项结论

### 1. 用户级子代理安装和卸载：无可利用问题

- **环境变量**
  - `CLAUDE_CONFIG_DIR`、`CODEX_HOME` 只在是绝对路径时才采用（`host-agent-install.ts:62`）。
  - 目录由调用方传入，本文件不读 `process.env`（`:3-4`）。
  - 能设环境变量的人本来就能指向任意目录。写入的文件名固定为 `tenon-<name>.<ext>`，内容是库里的渲染结果，没有越权面。
- **清单键被篡改，含 `../`**
  - 回收时只认能被 `parseHostAgentPath` 反解的键，名字必须匹配 `^[a-z0-9][a-z0-9-]{0,62}$`（`host-native.ts:52-60`）。
  - 实际路径由 `userHostAgentPath(agentsDir, host, parsed.name)` 重新拼，用的是 `basename`，不信任清单里的键（`install.ts:189-192`）。
  - 不会穿越。
- **清单分组键**：分组键是子代理目录，只当字符串比较，从不当路径用。
- **`__proto__` 之类的键**：用 `Object.fromEntries` 建对象，不会污染原型（`:78,94`）。
- **符号链接**
  - 目标文件是链接时拒绝写，回收时保留不删（`:157,197`）。
  - 临时文件用 `wx` 加唯一名，再 `rename`，不会写穿预置的链接（`host-agent-fs.ts:20-23`）。
  - 父目录是链接则放行，这是设计决定，用于 dotfiles 场景。
  - `configRoot` 和 `agentsDir` 本来就是用户自己的目录，这一点可接受。
- **清单损坏**：既不改也不删已有文件，且不写回清单（`:138,239-242`）。
- **并发**：读改写在 `withLock` 里完成。

### 2. 旧项目级文件清理：无可利用问题

- **定位主检出**
  - `mainCheckoutOf` 用 `execFile` 加参数数组，没有 shell；有 1.5 秒超时，输出上限 4KB；只认公共目录名为 `.git` 的情况（`main-checkout.ts:18-22`）。
  - 先看顶层 `.git` 是不是指针文件，再决定要不要起 git 进程（`host-agent-files.ts` 的 `legacyRootOf`）。
- **候选路径**
  - 只来自 `parseHostAgentPath` 通过的键或目录扫描结果，路径不会逃出两个 agents 目录。
  - 删除前检查父目录链上有没有符号链接（`hasLinkedParent`）、目标文件是不是链接，并要求内容与清单摘要或当前渲染一致。
  - 改过的文件一律保留。
- **残余**：`inspectFile` 之后到 `unlink` 之前有一个很小的竞态窗口。要利用它得先有主检出的本地写权限，而有这个权限的人本来就能直接删文件，所以不构成越权。

### 3. `hooks/step-progress.sh`：无可利用问题

- 抽名字的正则只取 `[a-z0-9][a-z0-9-]*`，且后面必须跟空白、分隔符或结尾（`step-progress.sh:32`）。
- `NAME` 不能带 `$`、反引号、`;`，也不能以 `-` 开头，所以没有命令注入，也没有选项注入。
- 命令只被当作文本匹配，不被执行。传给 tenon 时用 `"$NAME"` 加引号，且 `</dev/null`（`:43`）。
- 输入有 65536 字节的有界扫描（`:25`）。
- 输出经 `pipeline_json_escape` 转义后包进 JSON（`:48`）。
- 异常一律 `exit 0`。
- cwd 来自工具输入，只做 `cd`，不执行。
- 这里没有 `$(…)` 或 eval 面。

### 4. `tenon init` 建 worktree 和 `setup`：无可利用问题（有两条纵深提示）

- **任务名**：`CHANGE_NAME=/^[A-Za-z0-9_-]+$/`（`task-worktree.ts:43,61`），路径和分支都拼自这个名字。
- **git 调用**
  - 全部使用参数数组。
  - 路径或分支冲突时不覆盖；失败时回滚，回滚只删本次新建的路径和分支（`:126-131,156-173`）。
  - `.git/info/exclude` 只追加固定的一行。
- **setup 的信任约束**
  - 只在 `isTrusted(seal, catalogExecDigest(catalog))` 为真时才执行（`init-setup.ts:117`）。
  - 摘要按 worktree 里已提交的目录内容计算，主检出里有未提交改动就不匹配，不执行。
  - 继承信任时只复制 `trusted` 条目，不复制 approvals、writes、heads（`:25-40`）。
  - 封存被改动时读成空封存，不继承。
  - 子进程 stdin 不接，输出转到 stderr。
- **纵深提示（不单列发现）**
  - 信任是按命令摘要绑定的，不绑定目录内容的其他文件。setup 命令若调用仓库里的脚本，脚本被后续提交改了，摘要不变。
  - 这是既有的 `tenon test trust` 语义，不是本次引入。
  - `spawn` 用 `shell:true` 执行的是已被用户信任的字符串，符合设计。

### 5. `start_sha` 伴随文件和三个字段：无可利用问题（见 L2）

- **字段不可改**：`start_sha`、`base_branch`、`created_at` 经 CLI 不可改写，由 `tenon init` 独占写入（`field-values.ts:25-31`、`fields.ts:78`）。
- **提交 id 校验**：只接受 40 或 64 位小写十六进制（`change-start.ts:23`）。因此 `start_sha` 不会变成 git 选项或分支名。
- **伴随文件校验**
  - 键集、`schemaVersion`、`revisionId` 正则、`stateDigest` 都严格校验。
  - 与 revision 的身份和摘要不一致则抛 `RunStateCorruptError`。
  - 目标必须是非符号链接的普通文件（`start-sha-store.ts:53-80,84-88,137`）。
  - 发布用 `atomicLinkPublish`。
- **篡改的影响**
  - 要把 `start_sha` 改成更晚的提交以缩小改动范围，需要同时通过"是 HEAD 的祖先"和"提交时间不晚于 `created_at`+60 秒"两项校验。`created_at` 在受摘要保护的 wire 上。
  - 校验失败只会让起点前移，改动范围变宽，不会漏算（`change-start.ts:83-89`）。
  - 删除伴随文件的效果相同。
- **L2 的遗留面**：攻击者可以把 `start_sha` 改成"一个早于 `created_at` 的、仍是 HEAD 祖先的更晚提交"，使起点后移。这需要仓库里恰好存在这样的提交，且需要对 `.pipeline-run` 的写权限，已在候选里取"最新者"的规则下被限制。标为 low 的残余风险。

### 6. 指纹跳过未跟踪的 `.claude/worktrees/`：有一条 low

- **已跟踪的路径照常计入**，不能借此藏已提交的代码（`host-local.ts` 的 `skipUntrackedHostLocalDirs`，沿用 `skipUntrackedHostLocal` 的跟踪判定，含大小写折叠）。
- **git 无法回答跟踪状态时**，不跳过任何东西（`fingerprint.ts` 的 `tracking === undefined ? SKIP_NOTHING`）。
- **残余（L1）**
  - 未跟踪的 `.claude/worktrees/**` 内容不再进入 full 指纹，也就不绑进构建版本和评审候选。
  - 如果测试或构建命令执行这里的未跟踪脚本，改动不会让候选失效。
  - 测试记录绑的 portable 指纹本来就跳过它，所以不是新增的测试绕过面。新增的只是构建版本和评审候选这一侧。
  - 这个目录是宿主为子代理和会话建的检出，源码在真实路径上已计入，所以影响小。

## 发现清单

- L1（low）：full 指纹现在不计入未跟踪的 `.claude/worktrees/`。评审候选和构建版本不覆盖该目录里的未跟踪内容。需要本地写权限，且是设计声明的取舍。修法：在文档里写明，或在存在未跟踪 worktrees 目录时让评审报告提示。
- L2（low）：`start_sha` 伴随文件不在 wire 摘要里。本地写者可借"祖先加时间"的合法提交把起点后移。修法：长期可把 sha 的摘要并入 revision 摘要。
- L3（low）：卸载和回收在 `inspectFile` 与 `unlink` 之间存在 TOCTOU 窗口，利用它需要本地写权限，无越权收益。修法：可不处理。

## 残余风险

- 信任按命令摘要绑定，不绑 setup 所引用的仓库内脚本（既有语义，非本次引入）。
- 用户级清单和配置目录归用户所有，同用户的任何进程都能改。设计依赖"改过则不删"的哈希比对，已覆盖。
- 我没有跑测试，也没有核对构建产物 `packages/cli/dist/tenon.mjs` 与源码是否一致。
