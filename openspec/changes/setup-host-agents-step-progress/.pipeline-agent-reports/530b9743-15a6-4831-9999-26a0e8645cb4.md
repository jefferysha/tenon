# builder 报告：验证前审查第一轮的修复

主线派了两个只读审查（规格一致性；后端质量 + 安全），按下一步评审口径（medium 及以上为阻断）定级。本次运行修复其中的阻断项与低成本的低级项，共 10 项。

## 修复

1. **Dashboard 服务端旧文件清理补上「内容与当前库渲染一致」判据**（规格 host-native-subagents 第 131–133 行）。kernel 新增
   `renderCurrentFromLibrary`，CLI `currentRenderer` 与服务端 `hostAgentPrune.ts` 共用；服务端经 `TransitionDeps.hostAgentLibrary` 与任务生命周期路由装配读库，
   读库失败 WARN 后退回只按清单删。测试：`hostAgentPrune.test.ts` 4 例、`serverTaskLifecycleRoutes.test.ts` 1 例、`host-agent-files.test.ts` 4 例。
2. **`hooks/hooks.json` 去掉 step-progress 的 `"if": "Bash(tenon *)"`**：前缀过滤可能把 `cd x && tenon transition …`、`zsh -lc "tenon …"` 挡在脚本之外
   （计划 Review Focus 2）；脚本自己做零解释器窄过滤。`tools/test-hooks.sh` 改为断言没有 `if`。
3. **`tenon agent install` 不再误删**：解析失败、读失败、重名冲突的库条目按名字计入 keep；库里一个可用条目都没有时跳过回收并 WARN。kernel 2 例、CLI 2 例。
4. **卸载时被改过的文件结果列为 `modified`**（规格第 65 行原文），安装路径语义不变。
5. **补 CLI 集成用例 `definition-mismatch`**（回归覆盖，实现本来正确）。
6. **`hooks/router.sh` 跳过含 `;` 或 `=` 的 worktree 路径**（`change_candidate` 行的键值解析），`tools/test-hooks.sh` 新增小节。
7. **`tenon init` 的旧文件清理挪到建任务全部成功之后**，回滚时不再留下已删的旧文件；`init.test.ts` 3 例。
8. **文档写明 `setup` 的信任模型**：信任绑命令文本、不绑命令执行时读取的仓库文件（与测试套件相同），已信任的 `setup` 会在之后的提交改了这些文件时直接执行；
   不想自动执行用 `--in-place` 或去掉 `setup`（CONTRACT、quickstart 与 cli-reference 中英）。
9. **核对**：PreToolUse gate 只保护测试记录一类，不拦 `.pipeline-run/**`；canonical wire 靠读取时的摘要校验防篡改，而 `start_sha` 伴随记录的值不在摘要里
   （N-1 修复带来的缺口）。`isolation-mismatch` 的恢复办法（回 Build 重新捕获）使用文档已写。
10. **`start_sha` 读取时校验**（堵第 9 项的缺口）：记录的 `start_sha` 还须提交者时间不晚于 `created_at` + 60 秒（`created_at` 在受摘要保护的 wire 上）；
    不满足、读不到时间或 `created_at` 不可用就不作候选，退回上游 / 基线候选——伴随文件被改写或删除只会让改动范围变宽。
    `changed-files.test.ts` 新增 6 例（改写成建任务后的提交、边界 60 秒、建任务前的本地提交仍算、created_at 不可用、git show 失败与超时、argv 形状），
    3 个旧用例的前提随新规则调整了提交时间。CONTRACT 与 default-workflow（中英）、cli-reference 同步。

RED：第 1、2、3、4、6、7、10 项的新测试先因功能缺失失败（第 5 项为补充回归，第 8、9 项为文档 / 核对）。
