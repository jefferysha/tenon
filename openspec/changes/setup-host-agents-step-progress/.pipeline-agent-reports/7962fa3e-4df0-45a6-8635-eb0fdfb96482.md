# 安全评审报告：setup-host-agents-step-progress（候选 6344f94f…）

## 新增入口与出口

**入口**
- 环境变量 `CLAUDE_CONFIG_DIR` 和 `CODEX_HOME`。
- 用户可写的 `<configRoot>/agents/host-owned.json`。
- 工具输入里的命令文本（`hooks/step-progress.sh`）。
- 项目 `.git` 指针文件。
- 测试目录的 `setup` 字段。
- `tenon fields set` 的字段名。

**出口**
- 用户级 `agents/tenon-*.md|toml` 的写入和删除。
- 项目旧文件的删除。
- `git` 子进程（`execFile`，参数数组）。
- 经 shell 执行的 `setup`。
- 子进程 `tenon workflow progress`。
- `start-sha/*.json` 伴随文件。

## 逐项结论

1. **用户级子代理安装和卸载：未发现可利用问题。**
   - 配置目录只接受绝对路径（`host-agent-install.ts:62`）。
   - 文件名由 `hostAgentPath` 和 `parseHostAgentPath` 往返校验，挡住 `/` 和 `..`（`:152`）。
   - 回收时不信任清单里的键，绝对路径用当前目录和反解出的名字重新拼（`:189-192`）。
   - 清单解析用 `fromEntries`，没有原型污染（`:78-95`）。
   - 目标文件是符号链接则拒绝写入（`:157`）；回收时遇到符号链接则保留（`:197`）。
   - 写入用 `wx` 唯一临时文件加 rename（`host-agent-fs.ts:18-28`）。
   - 清单读改写在锁内完成；清单损坏时不删不改（`:138`）。
   - 篡改清单的人只能让 Tenon 删除"路径正确、名字合法、内容 hash 与清单记录一致"的 `tenon-*` 文件，没有越权。
   - `CLAUDE_CONFIG_DIR` 可指向任意绝对目录。这是用户自己的环境变量，属于本人信任边界，不单列为发现。

2. **旧项目级文件清理：未发现可利用问题，一处不确定。**
   - 只处理 `parseHostAgentPath` 能反解的 `tenon-*` 路径，内容必须与清单摘要或当前渲染一致才删（`host-agent-files.ts:167-168`）。
   - 逐级检查父目录符号链接（`:88-98`），目标本身是符号链接则保留（`:162`）。
   - 不确定：`legacyRootOf` 对 linked worktree 调 `mainCheckoutOf`（`:57-61`），我没有读该函数。恶意仓库的 `.git` 指针若指向别处，清理范围会落到那里。受上述内容匹配限制，只能删到内容与渲染结果完全一致的文件，影响很小。

3. **hook `step-progress.sh`：未发现可利用问题。**
   - 任务名只取 `[a-z0-9][a-z0-9-]*`，首字符不会是 `-`，所以不能注入选项（`:32`）。
   - 名字后面必须是空白、分隔符或结尾（`:32`）。
   - 变量加引号传给 `tenon workflow progress`，没有 eval，命令内容不会被执行（`:43`）。
   - 命令长度上限 64KB（`:25`）。
   - 输出经 `pipeline_json_escape` 转义（`:48`）。
   - `cwd` 来自宿主传入的值。`tenon` 是在该目录下运行，与用户手动运行无区别。

4. **`tenon init` 建 worktree 和执行 `setup`：未发现可利用问题，有一条 low 建议。**
   - git 调用全部是 `execFile` 加参数数组，带超时和 maxBuffer（`init-worktree.ts:21-27`）。
   - `setup` 只在测试目录的命令摘要在本用户信任记录里时才执行（`init-setup.ts:117`）。
   - 只继承 `trusted` 条目；approvals、writes、heads 不继承（`:25-40`）。
   - 摘要不一致（例如主检出有未提交改动）时拒绝执行，并提示用户自己信任，agent 不能代为确认（`:118-120`）。
   - `setup` 失败不影响 `init` 的退出码，也不抛错（`:133`）。
   - `shell: true` 在信任门之后使用，命令来自已信任的目录（`:67`）。
   - 子进程继承完整环境变量，且 stdout 和 stderr 原样转发。`setup` 命令若回显密钥，会进终端日志。这是低风险，信任门之后用户自己的命令。
   - 同名任务撞名检查先于建 worktree（`init-worktree.ts:63-72`）。

5. **`start_sha` 伴随文件和三个字段经 CLI 不可改写：未发现可利用问题。**
   - `fields.ts:78` 和 `field-values.ts:25-31` 把 `start_sha`、`base_branch`、`created_at` 列为只由 `init` 写入。
   - 伴随文件绑定 revision、revisionId 和 stateDigest，不一致即判损坏（`start-sha-store.ts:84-88`）。
   - 读取要求非符号链接的普通文件（`:137`）。
   - `sha` 必须是 40 或 64 位十六进制，`revisionId` 受 `SAFE_ID_RE` 约束（`:68-70`），所以不会路径穿越。
   - 发布用 `atomicLinkPublish`（`:117`）。

6. **工作区指纹跳过未跟踪的 `.claude/worktrees/`：未发现可利用问题。**
   - 只跳过 git 未跟踪的该目录；有跟踪内容则照常计入（`fingerprint.ts`，`skipUntrackedHostLocalDirs`）。
   - git 无法回答时不跳过任何东西（`tracking === undefined → SKIP_NOTHING`）。这是保守默认。
   - 残余风险：攻击者能往未跟踪的 `.claude/worktrees/` 里放文件，且不改变指纹。该目录本来就是宿主自己的 checkout 区，不属于实现候选，且已被明确声明。
   - 附带好处是不再递归遍历该目录，降低了拒绝服务风险。

7. **测试专用夹具进入发布的 CLI dist：有一条 low 发现。**
   - `packages/cli/tsconfig.json` 已把 `init-worktree-test-support.ts` 加入 exclude。
   - 但 `tools/check-architecture.mjs:479-492` 的"禁止出现在 dist"清单没有加入该文件的 `.js` 和 `.d.ts`。这样 exclude 一旦被误删，检查不会兜底。
   - 我没有运行构建，当前 `packages/cli/dist` 里没有该文件名。

- `host-owned.json` 被篡改的最坏影响，是 Tenon 删除自己写过且未被修改的 `tenon-*` 文件。
- 依赖清单和锁文件：我没有看到本任务触及新的第三方依赖，也没有逐文件核对 `package.json` 和锁文件的差异。
