## 发现清单

1. `packages/cli/src/commands/init-worktree.ts:54`：同名任务检查与 `createTaskWorktree` 之间有 TOCTOU 窗口。两个并发的 `tenon init` 同名任务可能都通过检查。修法：建 worktree 后（或持锁时）再校验一次，或依赖分支/路径冲突报错并补一个并发测试。
2. `packages/cli/src/commands/init-worktree.ts:63`：`assertNoSameNameChange` 只检查 `deps.cwd` 下的 `openspec/changes/<name>`。如果已有同名任务只存在于另一个 worktree，这里发现不了。修法：确认设计意图，并在文档里注明这个范围，或同时扫描已有 worktree。
3. `packages/cli/src/commands/agent-install.ts:133`：`kept > 0` 的汇总信息走 stdout。`setup` / `update` 经子进程调用本命令，所以汇总是给用户看的，这是有意的设计。但文案没有区分"foreign"和"modified"，用户无法据此判断下一步。修法：汇总里分别带上两类的数量。
4. `packages/cli/src/commands/agent-install.ts:109`：`loadAgentLibrary` 抛错时，stdout 已经输出过"目标目录"，随后以退出码 1 结束。这没问题，但失败路径缺少测试覆盖的证据（没有核对 `agent-install.test.ts`）。修法：补一条库加载抛错的用例。
5. `packages/kernel/src/infrastructure/host-agent-fs.ts:18`：`writeAtomic` 的 rename 目标如果已经是目录或符号链接，会直接替换符号链接本身。调用方依赖 `inspectFile` 先判断，这条约束只写在注释里，函数本身没有保护。修法：在注释里点明调用前必须先调用 `inspectFile`。
