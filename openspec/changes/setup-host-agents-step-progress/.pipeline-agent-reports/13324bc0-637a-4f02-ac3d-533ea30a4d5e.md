## 改了哪些旧断言（`fingerprint.test.ts`），为什么

1. 「完整指纹与 0.3.0 逐位相同」：按平台表里的 `plain:with`、`settings:with` 四个值（darwin、linux 各两个）是在含 `.claude/worktrees/x/y.js` 的夹具上算的，新规则下必然不等，已从按平台的表里拿掉；
   `fixture` 加了 `worktrees?: boolean`（缺省 true，只在 `hostLocal` 时生效，其它用例不变）；`with` 两项改用 `fixture({ hostLocal: true, worktrees: false, symlink: false[, sharedSettings: true] })`，
   单独成常量 `V030_HOST_LOCAL_FILES_ONLY`（与平台无关，注释写明原因与算法）。`plain:without`、`settings:without` 一字未动。**这两个值的占位待补，见「阻塞」。**
2. 「改、加、删宿主本地文件不动可移植指纹，动完整指纹；清单之外的同类文件仍属于候选」：旧用例把 `settings.local.json`、`CLAUDE.local.md`、`.claude/worktrees/` 的改动放在一起，
   断言完整指纹会变（旧规则：worktrees 也让它变；而且这样写 worktrees 的贡献被另两项掩盖）。拆成三条：
   - 改/删 `settings.local.json`、`CLAUDE.local.md`：`.full` 变、`.portable` 不变（旧语义保持）。
   - 未被跟踪的 `.claude/worktrees/` 改、加、删：`full` 与 `portable` 都不变（新规则；还断言与不含该目录的同一棵树一致）。
   - 清单之外的同类文件（lookalikes）：原循环原样保留，改在 `fixture({ hostLocal: false })` 上跑（等价于旧用例删光宿主本地文件之后的状态）。
3. 「被跟踪的 .claude/worktrees 代码」（git 小节第一条）：旧断言 `untracked.portable !== untracked.full`（完整指纹把未跟踪的 worktrees 算进去）和 `tracked.full === untracked.full`（完整指纹不看跟踪）
   都是旧规则，已反过来：未跟踪时 `full` 与 `portable` 都等于「还没有该目录」时的值；`track` 之后 `full` 与 `portable` 都变；改被跟踪文件两者都变；同目录未跟踪文件的改动与新增两者都不变。
4. `describe('host-local files')` 与 `describe('host-local files tracked by git')` 的头注释按新规则改写。
