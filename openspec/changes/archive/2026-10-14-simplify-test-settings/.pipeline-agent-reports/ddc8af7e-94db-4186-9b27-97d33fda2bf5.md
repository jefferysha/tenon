## 遗留问题
- **两处属主检查无法分开测**：属主测试用 `getuid` 桩同时覆盖目录和密钥。要单独造出属主是别人的文件，需要 root 权限。
- **CLI 用例无法只改 levels**：用例里的临时目录不是 git 仓库，套件也会显示为新增。「只改 levels 时不再落到兜底文案」的精确断言在 `protected-summary.test.ts` 里。
- **hook 识别仍是尽力而为**，以下写法识别不到，都已写进 `trust-command.sh` 头部：
  - 内联开关前面带「开关加单独一个值」的调用，例如 `node --require ./x.js -e …`、`python3 -W ignore -c …`；
  - 拼接或编码出来的字样；
  - 新写脚本里对状态目录的改写。
- **`protected-writes.sh` 行数**：现在 639 行，main 上是 632 行。新增逻辑已尽量放进 `trust-command.sh`（192 行）。
- **整条命令判定宁多拒**：路径里带 `tenon` 的 `node -e` 读 `HOME` 也会被拒。
- **缺库时的失败关闭**：`protected-writes.sh` 缺失时，输入里只要出现 `trust` 就拒。这属于安装缺陷，装好即恢复。
