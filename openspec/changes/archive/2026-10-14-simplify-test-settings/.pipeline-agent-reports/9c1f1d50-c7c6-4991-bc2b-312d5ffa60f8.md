### 边界 8：目录写回与 `--auto`

**精确路径**
- 候选只来自本任务改动列表，经 `withoutControlPaths` 和 `looksLikeTestFile` 过滤。改动列表来自 git，是仓库相对路径，`../` 不会出现。
- `relativeTo` 要求 `path` 以 `suite.cwd/` 开头，否则不认领。

**写回校验**
- `patchCatalogText` 做三道检查：
  - 原文重新解析的结果必须与 `before` 一致，否则抛错，文件在读取后被改过就拒绝改写。
  - 改动后的文本必须能重新解析。
  - 重新解析的结果必须与 `after` 的 canonicalJson 一致，否则抛"拒绝写盘"。
- 带 `#`、`: `、引号、换行等的路径经重新解析比对后，不一致就抛错。

**没有发现问题。** 我没读 `catalog-patch-lines.ts`，也没读中间的列表合并部分，但三道校验兜住了任何不一致。

## 发现

1. **medium：报告里的豁免理由没有转义。** 位置 `packages/cli/src/test-system/report-md.ts:101`。
   - 追溯矩阵里的 `row.waiver.reason` 是登记者自述，只经 `cell()` 转义了 `|` 和换行，没走 `escapedWaiverText`。
   - 登记者可以写 `[链接](url)`、`![图片](url)`、`<br>`、反引号或原始 HTML。进了报告和评审请求，会出现伪造链接或伪装成评审者的内容。
   - 同一份报告的步骤豁免小节已经做了转义，这里不一致。
   - 修法：这里改用 `escapedWaiverText(row.waiver.reason)`。
   - 影响：这是内容伪造，不是代码执行。

2. **medium：证据文件规则可以藏内容。** 位置 `packages/kernel/src/workspace/test-evidence-files.ts:39`。
   - `test-results/`、`playwright-report/`、`coverage/` 这三个目录名在任意深度生效。
   - 这些目录下未被 git 跟踪、扩展名为 `html`、`htm`、`json`、`md`、`zip`、`gz`、`mp4` 等的文件，不计入候选指纹。
   - 参与者（agent）可以把会被测试或页面加载的内容放进去，改它之后候选指纹不变。例如 `coverage/x/fixture.json`，或 `coverage/**.html` 里带脚本的页面。
   - 这是已书面记录的取舍。我评估下来它确实达到 medium。
   - 修法：要么只放行预期的几个子目录，要么把 `html`、`htm`、`zip`、`gz`、`json` 移出名单，由目录声明来放行。

3. **low：报告里的其他自述文本没有转义。** 位置 `report-md.ts:195-204`。
   - `ref`（flaky 与失败项）和 `item.message`（仍挡出口的项）里的文本直接拼进 Markdown。
   - 这些来自测试名和系统消息，目前没发现不可信输入能进来。
   - 修法：统一走转义函数。

4. **low：同一路径换仓库后继承信任。** 设计文档已记为剩余风险。
   - 信任按仓库身份（common dir 路径）记录。路径相同但内容已换成别的仓库，旧信任仍然有效。
   - 摘要覆盖命令本身，所以只有"同一条命令"被继承。
   - 修法：身份里加入首次提交哈希或远端 URL。

5. **low：hook 没有第二道防线。**
   - `test-trust` 目录的写入只靠 `protected-writes.sh` 的文本识别拦截。
   - 修法：运行时再加一道校验，比如在 `tenon test trust` 里要求交互式终端（TTY），或检查信任存储的修改归属。

6. **low：`stepTestsExecDigest` 排序比较器。** 位置 `packages/kernel/src/test-system/catalog.ts:150`。
   - `id` 与命令都相同时返回 1 而不是 0，整份摘要在重复条目下顺序不稳定，只影响旧封存兼容的稳定性，不影响安全。

## 残余风险
- 非 git 仓库仍认检出目录里的旧封存。压缩包自带的封存拦不住。这是已知取舍。

- 同一路径换成另一个仓库后继承信任。
- 请求体先以 `unknown` 收窄这一条没有核对（不在本次 diff 里）。
- `catalog-patch-lines.ts` 没有读（后端质量评审者已逐行读过）。
