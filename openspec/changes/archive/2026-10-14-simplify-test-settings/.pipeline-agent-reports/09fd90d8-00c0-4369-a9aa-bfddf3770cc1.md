## 实现步就绪审查（四路，Sonnet low，按 `review_bar`，完整覆盖）

第一次就绪审查：
- spec-consistency、backend-quality、code-size 没有 medium 及以上；
- security 报 1 条 medium：信任存储位置由 `TENON_RUNTIME_HOME` / `TENON_RUNTIME_ROOTS` / `XDG_STATE_HOME` / `HOME` 决定，agent 能把它指到自造的存储。

修法与复核：
- 修法照评审建议之二，与 `TENON_TEST_TRUST` 同一做法、同一强度：hook 拒绝 agent 改写 Tenon 的状态目录。
  - 两个运行时根变量的前缀赋值与 export 一律拒。
  - `HOME` / `XDG_STATE_HOME` 的 export 与单独赋值一律拒；作为前缀赋值，只在同段命令头是 tenon 时拒。
  - 另加保守兜底：值边界存疑（引号包住整个赋值、带 `$`、括号等）且同段有 tenon 记号时拒。
- 识别逻辑拆到新文件 `hooks/lib/trust-command.sh`，缺失时失败关闭。`hooks/lib/protected-writes.sh` 降到 628 行，比 main 的 632 行短。
- 代码层不改路径解析：测试隔离依赖 `TENON_RUNTIME_HOME`。
- `tools/check-architecture.mjs` 只放行 `trust-command.sh` 点名这两个变量（它只拒绝设置、从不解释其值），注释写明原因。
- 复核：security 确认这条 medium 已按纵深防御口径修好，又报 2 条漏判 low（引号包住的赋值、`$(…)` / `${…}` 的值），已由兜底收掉。code-size 复核没有 medium。

本轮一并收掉的 low：
- `stage-run-set` 的改动路径与认领同一口径归一（`changedRepoPaths`）；
- 报告里指标名先截短再转义；
- 「要求映射时照旧」与现行 default 档位在 `next` 层的端到端用例；
- 展示给 agent 的不可信文本：benchmark 行、skipped 行、委托拒绝信息、未认领路径；
- 无状态目录时的信任提示；
