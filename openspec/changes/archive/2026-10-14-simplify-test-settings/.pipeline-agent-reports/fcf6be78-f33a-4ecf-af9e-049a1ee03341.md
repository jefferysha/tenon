## 2. 发现清单

**F1（medium）`kernel/test-system/stage-run-set.ts:73-83`**
`changed` 档只跑被改动"碰到"的套件，碰到的判据是套件 `files` 或 `covers` 命中改动路径。自动识别（`cli/test-system/auto-discover.ts`）生成的套件没有 `covers`，所以只改非测试源码时运行集为空。求值此时没有任何阻断，也没有提示，步骤在零测试执行的情况下通过。`design.md:47` 只对 `full` 档提到依赖 `covers` 写得准确，`changed` 档的这个静默通过没有文档说明。
修法：运行集为空且改动里有非控制目录的源码文件时，在求值里出一条 notice（例如 `no-suite-touched`），或让没有 `covers` 的套件被任意非测试源码改动碰到。

**F2（low）`kernel/test-system/trust-store.crossprocess.helper.ts:1`**
测试辅助脚本放在 `src/` 下，名字不以 `.test.ts` 结尾，会被 `tsc` 编译进 kernel 产物。顶层 `await` 加参数校验，没有入口引用它，实际无害。
修法：改名为 `*.test-helper.ts` 并加入 tsconfig 的 exclude，或移到测试目录。

**F3（low）`cli/commands/review-waivers.ts:200,206`**
`refuseDelegatedWhileWaiversPending` 抛错时，把豁免 key 和受保护改动路径原样拼进错误信息，没有走 `foldDisplayText`。错误信息会被 agent 读到，路径里的换行或反引号能改写行结构。同文件的评审请求打印已清理，这里漏了。
修法：这两处也走 `displaySafeText` / `foldDisplayText`。

**F4（low）`cli/commands/test-trust.ts:147-149` 与 `:242`**
`ensureTrusted` 在 git 仓库、`stateRoot` 缺失时仍提示运行 `tenon test trust`，而该命令会直接失败。这是已知项（无状态目录时提示不一致），级别维持 low。`test-trust.ts:242` 的失败信息已经说清原因，用户体验上是多绕一步。

**F5（low）`kernel/test-system/trust-store.ts:123,205`**
存储文件超过 8MB 或封印不符时读成空，随后 `addTrustEntries` 从空起步重写，原有信任整份丢弃。文档已写明，需要用户重新确认。容量上限 2000 条与 8MB 之间差距很大，正常路径不会触发。

**F6（low）`hooks/lib/protected-writes.sh:27`**
`*/test-trust/*` 对任意项目路径生效，项目里恰好有名为 `test-trust` 的目录时，agent 的写入会被拒。这是有意的保守取舍，注释已说明。信任存储本身不是密码学防御：`TENON_RUNTIME_HOME` 或 `TENON_RUNTIME_ROOTS` 可以把 `stateRoot` 指到别处，但伪造存储仍要写入含 `/test-trust/` 的路径，被同一条规则挡住，所以保护依赖 hook 的识别覆盖面。

**F7（low）`cli/commands/test-register-auto.ts:35`**
`unresolvedMessage` 把未认领的文件路径原样拼进错误信息，文件名由仓库内容决定，同 F3 的展示清理问题。
修法：走 `foldDisplayText`。

## 3. 残余风险

1. **信任存储的强度取决于 hook。** 同 UID 的恶意进程读到密钥就能重算封印，保护靠"写入受保护路径被拒"加"agent 的 Bash 里不能出现 `tenon test trust` 与 `TENON_TEST_TRUST`"。hook 对 shell 写入形态的识别是启发式的，已有 13 种形态加本次新增用例，但不是形式化保证。
2. **仓库身份读不出时一律未信任。** 这是对的取舍，代价是 git 超时（10s）或 worktree 异常时用户要先修 git，才能写入信任。
3. **`changed` 档在没有 `covers` 的目录上静默通过**（F1）。`full` 档的必需类不看改动，不受这一条影响。
4. **指纹排除未跟踪证据文件，依赖一次 `git ls-files`。** 它在每个最外层测试输出目录各起一次子进程，git 不可用时退化为全部计入，只会让指纹更保守，不会漏计。
5. **并行任务 `rework-document-mechanism` 的合并分叉**按派发说明不在本次评审范围。
