## 已知取舍与偏差（如实列出，供验证步评审）

- `plan` 档不运行任何套件，即使计划里显式登记（规格「所有档位追加显式套件」与「plan：不运行套件」有张力，取后者；改动只需 `stage-run-set.ts` 的 `levelRunSet` 开头一行）。
- `plan` 档不读改动列表：读不到改动不出 `files-diff-unavailable`、不查孤儿（设计 §Q3 / checkFiles 只对 changed、full；规格「所有档位」措辞更宽）；有专门测试「plan 档读不到改动列表与本步无关」。
- `test-waived` 提示把实测值放在同一行（先写实测值再写登记者自述的理由），规格写「另起一行」；评审请求清单、验证报告、评审者提示三处是单独一行。提示保持单行是为了终端 / Dashboard 单行展示与防注入。
- 旧 `test_policy` 的 `scenarios: off` 步骤，追溯矩阵同样收成统计行（只影响报告格式与行的 `required` 标记，门禁结论不变）。
- `--stage` 读不到改动列表时打印 WARN 并按计划运行，`status` 仍出 `files-diff-unavailable` 阻断，门禁不放行。
- `test: none` 进 IR：写了它与不写的工作流指纹不同；没写 `test` 的工作流编译结果与指纹逐字节不变（快照测试）。
- `levels` 同时计入 `catalogDigest` 与 `catalogSuitesDigest`：改档位定义，已有运行随之过期；不写 `levels` 时摘要不变。
- `--auto` 只改目录 glob 的精确路径，不写计划；认领在求值时计算。
- 证据文件指纹规则按规格逐字实现（目录名任意深度、规格列出的扩展名名单、仅未跟踪文件、失败关闭）；非 git 仓库按失败关闭，目录下文件照算。评审者提出「名单含 html/zip、任意深度」的风险，但收窄会与已登记规格相悖，未改。
- 非 git 项目里压缩包自带的旧封存与密钥仍能授信（规格要求非 git 项目退回旧封存）。
- 本仓库 `.tenon/tests/catalog.yaml` 按设计 Q12 不写 `levels`，未改。
- 豁免理由里的裸 URL 仍会被 GFM 自动链接（只显示为文字链接，不加载图片）。
- Dashboard 旧策略只读摘要的标签是「策略」，来源行带重复 `title`（评审 low，未改）。
- 本机 clean-install 的受信 Codex 工具根不能放在 `/tmp` 下：install.sh 在 macOS 上用 `stat -f %Lp` 读不到粘滞位，把 `/private/tmp` 判为不可信（既有问题，与本任务无关；CI 为 Linux 不受影响），本地改放 `~/.cache` 下，并照 CI 换成 Node 22。两次验收跑完工作区无任何改动。
- 执行者 I 在 scratchpad 里验证 git pathspec 行为的临时脚本含对 `.tenon` 的删除命令被 gate 拦下一次，改用别的目录名重跑；没有操作任何真实受保护路径。
