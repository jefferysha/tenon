## 发现

- L1（low）：`endedTasks.ts` 对 `archive/` 做无上限的 `readdir`，之后才按时间截断到 1000。归档目录极大时每次项目重建仍有 O(N) 的 `readdir` 开销，加每个新目录一次 `lstat`。这只在本机用户自己无限增长归档时才会触发，没有外部触发路径。修法：在 `readdir` 后设条目数硬上限，或在归档目录里分桶。
- L2（low）：已提交的测试运行记录里有本机绝对路径，如 `/Users/a1234/Documents/code-manager/projects/te…`，来自堆栈。这是泄漏本机目录结构和用户名的信息，没有凭据。修法：写记录时把绝对路径归一成仓库相对路径，或提交前脱敏。
- 观察（不计级别）：`commitOnlyPaths` 在任务目录已被 git 跟踪时，除 `archivedDir` 外会再带上 `openspec/changes/<change>`。两者都是被移动的同一个任务目录，符合设计，并没有扩大范围。`openspec archive` 是 PATH 上的本机二进制，沿用既有信任模型。

## 残余风险

- 本轮没有展开 `readProtectedChanges` 的实现，也没有通读工作流写接口的每条路径，只核对了编译层的校验。我没有审 `*.generated.ts` 和 `dist/**`。
- `router.sh` 里打分用的 `grep -E` 靠转义保证字面匹配。我只读了转义和消费位置，没有逐字节验证 grep 的所有方言。
- 归档里的任务锁目录在 `dropMovedLock` 中清除失败会被忽略，只留下无主空目录，属于可用性小瑕疵，不是安全问题。
