## 发现

- **L1（low）**：`router.sh` 把缓存解码出的 pattern 原样交给 `grep -E`，没有检查 pattern 的形状。正常路径下 pattern 由 kernel 转义成字面量备选式，缓存也在 `.gitignore` 里，不会随 PR 带进来。但本机能写 `.pipeline/cache/` 的人或进程可以伪造缓存：只要算出与现有工作流一致的摘要，就能放进带回溯的 ERE，让每次 prompt 的 grep 变慢。前提是已有本机写权限，所以只是纵深防御。修法：shell 端对 pattern 只允许转义后的字面量字符集，或给 grep 加超时。
- **L2（low）**：delete 和 terminate 的 `warnings` 原样回传内核告警，其中带暂存绝对路径（`task-lifecycle.ts:374`）。只有持 token 的本机 Dashboard 用户看得到。`archive-failed` 的 `outcome.cause` 带 openspec 的 stderr，属于已有行为。修法：只回传相对路径或告警码。
- **L3（low）**：`test-results/dashboard-e2e-server` 里有 e2e 被测服务的一次性登录链接日志。本地已被 gitignore 排除，不会提交。若 CI 把它作为制品上传才会外泄，这一点主线另行核实。修法：确认不上传，或在日志里脱敏令牌。

## 残余风险

- 第 2 轮提到的两条 low 是否仍成立：
  - `listEndedTasks` 对 `archive/` 的 `readdir` 仍无条目数硬上限，只在返回时截到 1000（`endedTasks.ts:237`），本机用户自己无限增长归档才会触发，没有外部路径。
  - 我这轮没有重新检查已提交测试运行记录里的本机绝对路径，沿用上一轮结论，状态为未复核。
- `archive-failed` 响应里的 `outcome.cause` 可带绝对路径，属于历史行为，非本次引入。
- `readProtectedChanges` 的 `digestOfFile` 是否跟随最后一级符号链接，我没有展开。路径已经过 `staysInside`，存在检查与读取之间的竞态窗口只是理论上的。
- 没有审 `*.generated.ts` 和 `dist/**`。

## 主线核实（不改变评审者结论）

L3 的 CI 上传问题，主线读了 `.github/workflows/ci.yml:104-114`：
- 只有 Dashboard e2e 步骤失败时（`if: ${{ !cancelled() && steps.dashboard-e2e.outcome == 'failure' }}`），CI 才把 `playwright-report/` 与 `test-results/` 整体作为制品上传，保留 7 天。
- 这是任务开始前就有的行为。e2e 服务在 `main` 上就把日志写进这个目录，本任务的 catalog 声明只影响 Tenon 的候选指纹，不改变上传范围。
- 日志里的登录码是一次性的，2 分钟内有效，对应的被测服务随 CI job 结束而退出。
- 结论：L3 维持 low，不是本任务引入的问题。
