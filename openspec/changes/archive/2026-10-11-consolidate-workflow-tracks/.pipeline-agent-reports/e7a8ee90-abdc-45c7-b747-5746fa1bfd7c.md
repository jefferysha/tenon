## 第三部分：改动最多的已有文件

- **`kernel/workspace/task-lifecycle.ts`**：见第一部分第 1、2 项。delete 在锁内先 `sweepTaskTombstones`，再评估，再 `stageTaskForDelete`，最后审计；审计失败只进 `warnings`。
- **`hooks/router.sh`**：
  - 缓存加载是严格的 data parser：版本头、`M` 行的根路径校验、`R` 行逐字段 hex 白名单、`_uint_ok`、序号递增、64 行上限、未知记录类型直接拒绝，没有 `source` 或 `eval`。
  - 点名正则用 `[[ =~ ]]`，匹配文本用带引号的 `"$match"` 做模式切分；标签用 `$lead"$label"$trail`，标签按字面量匹配。
  - `set -uo pipefail` 下全部数组都用下标和 `${#arr[@]}`，没有 `"${arr[@]}"` 展开空数组，bash 3.2 下不会触发 `unbound variable`。
  - 冷路径失败时 `exit 0`（不拦用户）；缓存先写 `mktemp` 临时文件，校验通过后再 `mv`；热路径零解释器。
  - 备注：`grep -ciE -- "$pattern"` 的 pattern 来自项目可写的缓存，被篡改且摘要仍匹配时可能引入病态 ERE。内核编码时已转义，本地缓存被篡改属于同信任域，不单列。
- **`hooks/router-gen.mjs`**：只做 `realpath`、调 kernel 的 `generateRouterCache`、把警告写到 stderr；`loadKernel` 失败返回非 0，由 `router.sh` 兜底。
- **`cli/commands/task.ts`**：新增 `terminate`、`finish`，`archive` / `unarchive` 退役并报错。`args[0] ?? ''` 经 `isTaskLifecycleName` 校验。
- **`server/snapshotProjectScan.ts`**：`listEndedTasks` 的 Promise 先创建、后 await；它内部吞掉了所有单目录错误，不会成为未处理 rejection。已结束任务的缓存按根分，上限 256 个根。
- **`statusStep*.ts`、`advance*.ts`、`check.ts`、`templates/workflows/default.yaml`**：只做 diff 级扫描，没有发现新的 `as` / `any` 或接缝外比较。

## 发现清单

1. **medium**，`packages/server/src/serverTaskLifecycleRoutes.ts:259-262`（delete 响应）：`handleTaskLifecycleDelete` 成功响应丢掉了 `outcome.warnings`，删除后审计行没写进去时 Dashboard 完全看不到（CLI 会打 `WARN:`）。修法：响应里和 terminate 一样附带 `warnings`，前端有展示位时一并展示。
2. **low**，`packages/kernel/src/workspace/archive-task.ts:234-244、295`：`moveByRename` 的 `rename` / `mkdir` 以及 `moveByOpenspec` 里把活跃目录改成带序号名的 `rename` 抛出的原始 `Error`（如 EXDEV、EACCES）不是 `ArchiveTaskError`。`task_result` 虽被清回，但 `task-lifecycle.ts:306-307` 的 `guarded` 会把它重新抛出，CLI 和服务端得到未归类的异常，与「归档失败是 outcome，不是崩溃」的设计不一致。修法：在 `archiveTask` 的 `catch` 里把非 `ArchiveTaskError` 统一包成 `move-failed`。
3. **low**，`packages/kernel/src/workflow/legacy-phase-manifest/legacy-execution.ts:~24`：`event in DEFAULT_EVENT_POLICY` 会命中原型键（`constructor`、`toString`），随后读 `.guards` 得到 `undefined`。修法：改用 `Object.hasOwn`。
4. **low**，`packages/kernel/src/workspace/task-lifecycle.ts:334-336`：`lockedEnding` 在评估和阻断判断之前先清残留的 `task_result`。残留只在崩溃后出现，清除也只在它非空时发生，但被拒绝（如 AFK 运行中）的 terminate 也会写一次状态修订，与文件头「拒绝则不写」不完全一致。修法：把清除放到 `refuse` 之后，或在文件头注明例外。
5. **low**，`packages/cli/src/commands/exitGuards.ts:41`：`sameGuard` 用 `JSON.stringify` 比较，对对象键顺序敏感，结构相同但键序不同的 guard 不会被去重。修法：用稳定序列化或结构比较。
6. **low**，`packages/server/src/serverTaskLifecycleRoutes.ts:~142、~199、~233`：`decodeURIComponent(match[1])` 遇到畸形百分号编码会抛 `URIError`。这是既有写法，不是本次引入，但新增的 terminate 路由沿用了它。修法：包 `try`，畸形时返回 400。

## 残余风险

- AFK 运行器置位 `automation=running` 是否持有同一把任务锁，我只核对了锁用法，没追到运行器的写入点。如果它绕过任务锁写状态，第一部分第 1 项的互斥仍有窗口。建议在集成测试里加一个 terminate 对 AFK 启动的并发用例。
- `archiveDirIsTask` 对 `foo` 的第二份归档与任务 `foo-2` 的归档分不开，文件头已说明并接受。
- `hooks/router.sh` 的摘要和 Node 侧对非 UTF-8 的工作流文件会不一致（每轮重建缓存，路由结果仍正确，只是慢），文件头已说明。
- 我没有跑任何测试或脚本，以上都是静态读码的结论。
