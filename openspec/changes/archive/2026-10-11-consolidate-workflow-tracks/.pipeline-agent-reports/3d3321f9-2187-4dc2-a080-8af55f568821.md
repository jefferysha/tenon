# builder 报告（实现步第 4 轮）

## 背景

验证第 3 轮：测试全部通过，但主线在验证步跑了 Dashboard e2e，`verify-pass` 因此被 `revision-stale` 挡住。

- e2e 的服务脚本 `e2e/dashboard/support/serve.mjs` 把状态和日志写进 `test-results/dashboard-e2e-server/`。
- 测试目录没有声明这个目录。Tenon 的候选指纹会把 `test-results/` 下未声明的文件算进候选，所以每跑一次 e2e，`build-complete` 冻结的构建版本就失效一次。

本轮不改业务代码，只修这个根因。

## 改动

- `.tenon/tests/catalog.yaml`：`dashboard-e2e` 与 `dashboard-e2e-chromium` 的 `artifacts` 各加一行 `test-results/dashboard-e2e-server`。用 Edit 改，注释与其余内容不变。
- `packages/cli/src/e2e-test-outputs.test.ts`（新增）：
  - 用 kernel 的 `declaredTestOutputs(仓库根)` 断言该目录被声明，判定口径与 `fingerprint.ts` 的 `isDeclaredOutput` 相同。
  - 读源码文本，断言 `serve.mjs` 的 `STATE_DIR` 和 `server-state.ts` 的 `SERVER_DIR` 仍是这个目录。
  - 服务目录改名或 catalog 漏声明时，这个测试会变红。

builder 起初把防回归测试写成 `tools/*.node-test.mjs`。它读 catalog、文件里含 `.tenon`，又还没入库，用 `node --test` 直接跑会被 gate 拦下；builder 停下回报，没有绕过。主线决定改写成 vitest、用 kernel 自带的解析器，同时也去掉了对 `yaml` 包的隐式依赖。那个 mjs 文件已删除。

## 测试

- RED（catalog 还没改）：`npx vitest run packages/cli/src/e2e-test-outputs.test.ts` 有 1 个用例失败（`test-results/dashboard-e2e-server 不在声明输出里`），另 2 个通过。
- GREEN（改 catalog 后）：3 个用例通过。主线复跑同一命令，3 passed。
- `tenon test catalog validate`：有效（33 个套件，1 个服务），exit 0。
- `npm run check:comments` 通过；`npx tsc --noEmit -p packages/cli/tsconfig.json` 无错误。
