# builder 报告（实现步第 3 轮）

本轮修验证第 2 轮 backend-quality 的 1 条 medium 与 5 条 low，补 spec-consistency 指出的测试缺口。三个 builder 子代理在同一工作区里串行执行，主线逐项核对了改动并重跑了测试。

## 任务 A：后端评审意见

| 项 | 文件 | 改动 |
|---|---|---|
| medium：delete 响应丢 warnings | `packages/server/src/serverTaskLifecycleRoutes.ts` | DELETE 成功响应在有警告时带 `warnings`，写法与 terminate 一致 |
| low：畸形百分号编码抛 URIError | 同上 | 新增 `decodeChangeName`（失败返回 null）与 `sendInvalidName`；GET lifecycle、POST terminate、DELETE 都返回 400 `invalid-name`；GET 的两次解码合成一次 |
| low：裸 fs 异常冲出 guarded | `packages/kernel/src/workspace/archive-task.ts` | `archiveTask` 的移动 `catch` 把非 `ArchiveTaskError` 包成 `move-failed` 再回滚；回滚位置语义不变 |
| low：原型键命中事件表 | `packages/kernel/src/workflow/legacy-phase-manifest/legacy-execution.ts` | `event in` 改为 `Object.hasOwn` |
| low：guard 去重对键序敏感 | `packages/cli/src/commands/exitGuards.ts` | `sameGuard` 改用 `isDeepStrictEqual` |
| low：被拒绝的终止也写一次清理修订 | `packages/kernel/src/workspace/task-lifecycle.ts` | 只补文件头说明（第 1 轮要求在锁内、评估之前清残留，顺序不动） |

测试：`serverTaskLifecycleRoutes.test.ts`、`archive-task.test.ts`、`task-lifecycle.test.ts`、`execution-seam.test.ts`、`exitGuards.test.ts` 新增用例，先红后绿。RED 摘录：

- delete 响应缺 `warnings`
- 三个路由畸形编码得到 500
- 归档时抛出的是裸 `Error { code: 'EACCES' }`
- `constructor` 等原型键不抛错
- 键序不同的共有条件被丢掉
