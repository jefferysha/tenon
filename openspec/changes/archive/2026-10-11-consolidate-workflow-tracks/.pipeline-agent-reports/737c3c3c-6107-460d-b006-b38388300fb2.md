## 二、第 2 轮改动是否偏离规格

1. **统一锁序（先归档锁再任务锁）与移动后审计失败降级为警告**：不偏离。规格 R8 要求「在锁内原子移动」。`task-lifecycle.ts` 与 `archive-task.ts` 的头注释和 `lockedTask` 都按此实现，测试是 `task-lifecycle.integration.test.ts:198`。「降级为 `WARN:`、server 响应带 `warnings`」是规格没写的行为，见 L4。
2. **CLI 执行模型唯一判定点与 `execution-model-seam.mjs`**：对应设计「选择适配器的接缝必须唯一」。不算多做。
3. **读不到计划时结论字段写入闸拒写（`verdictFieldGate.ts`）**：属于失败关闭的安全收紧。对应测试是 `verdictFieldGate.test.ts` 和 `verdict-field-gate.integration.test.ts`。规格未明写，见 L5。
4. **归档目录精确匹配（`archived-task-name.ts`）**：服务 R3 `dependencies-ended`，不偏离。
5. **每条 `automation.eligible` 分支必须声明 AFK loop 的全部 phase（`custom-phases.ts`）**：服务 R11，不偏离。
6. **`tenon assess` 权限错误失败关闭（`assessPaths.ts`）**：符合设计 §6b 的安全约束。

## 三、发现清单

- L1：`tenon test sync --prune`（`packages/cli/src/commands/test-sync-prune.ts`）与 `tools/vitest.isolate-runtime-home.mjs` 是多出的能力，规格未记。你已说明是用户明确要求，只作提示，请规格补一句。
- L2：`tenon init --domain`（`taskDomain.ts`）对应设计 §2，但 delta spec 的 R5 只写了「沿用领域」，没写参数名。建议补一句。
- L3：`MAX_ENDED_TASKS = 1000`（`server/endedTasks.ts:52,263`）只截断返回的列表，同时返回 `total`。R9 写「列出全部归档任务」，与实现有差异。建议规格说明有上限，或确认 UI 在 `total` 大于返回数时有提示。
- L4：移动后审计或提交失败降级为警告（结果仍成功，CLI 打 `WARN:`，server 响应带 `warnings`），规格 R8 未写。属于规格未记的行为。
- L5：读不到计划时结论字段写入闸拒写，规格未记。
- L6：`tenon assess` 超限退出码为 3，用法错误、路径错误、无阈值为 1。规格只说「输出是否超限与理由」，未规定退出码。
- L7：设计 §6a 写「新任务不再经过 `flow/transition-table.ts`、`guard.ts` 的 `EXIT_RULES`」。这两个文件仍在 `kernel/src/flow/`，并被 `cli/commands/transition.ts` 和 `cli/events.ts` 引用，用于旧快照任务的转换判定。delta spec 只要求新任务按 YAML，没有要求删除旧代码，所以不判偏差。
