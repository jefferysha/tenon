## 验收条目对照

1. **回退免回执的唯一判定：达成。**
   - 实现：`backEdgeSkipsReview` 在 `packages/kernel/src/workflow/transition-rounds-gate.ts` 里是纯函数，经 `packages/kernel/src/index.ts` 导出。条件是：回退边、非放弃边、`rounds` 非 null 且非 undefined、轮次没用完。内核 `backEdgeRounds`、CLI 的 `gatedBackActions` 和 `exitActions` pending 分支都改用它。
   - 行为不变：`backEdgeRounds` 在调用前已先排除前进边、放弃边和 `rounds === null`，所以传 `back: true` 与原判定一致；`exitActions` 原来的 `direction === 'back'` 现在由 `back` 参数表达；内核和 CLI 的 `rounds` 为 null 时都失败关闭。
   - 测试：主线报告现有轮次和回退测试全绿。没有给 `backEdgeSkipsReview` 单独写表驱动单测，见 low。
2. **评审期只放行标记所属任务的 transition：达成。**
   - 实现：`hooks/gate.sh` 的 `gate_check_marker` 在调 `is_review_control_command` 之前，用 `pipeline_review_marker_change` 设置 `REVIEW_MARKER_CHANGE`；`pipeline_transition_command_ok` 末行要求它非空且等于命令里的 `<change>`。取不到任务名时一律不放行。
   - `cd x && tenon transition other-change …` 逐段判断，transition 段仍走同一个函数，所以被拦。`is_review_control_command` 只在评审标记下调用，确认和交互标记的行为没变。
   - 测试：`tools/test-hooks.sh` 新增 `other-change` 与 `cd /tmp && … other-change` 两条拦截用例；标记所属任务 `ro-demo` 放行的用例此前已有。
3. **只读名单收紧：达成。**
   - `rg`：`-z`、合并短选项（如 `-iz`）和 `--search-zip` 判非只读；`--no-search-zip` 不含 `--search-zip` 子串，仍放行。
   - `git diff|log|show`：`*--ext*` 和 `*--textc*` 前缀拦截，覆盖 `--ext-diff`、`--textconv` 及其缩写；`--no-ext-diff` 不含 `--ext`，仍放行。
   - 测试：`tools/test-hooks.sh` 有 7 条拦截和 3 条放行；主线证据显示旧库上 7 条被判只读（RED），修复后全部通过。
4. **文档与主 spec 同步：达成。** `docs/CONTRACT.md`、`adapters/contract.md`、`docs/usage/{,zh-CN/}` 下的 `cli-reference`、`release-notes`、`troubleshooting`，以及 `openspec/specs/interaction-and-skill-provenance/spec.md` 都有对应改动。
