sidecar 步序号同步：stderr 差异 `21/25/27/28` -> `15/23/25/26`；exit 差异 `25` -> `23`。这是同一批步骤换了编号（barrier、第 2 轮 verify-pass、ship-complete、archived），登记的理由文案一字未改。

## 场景 A–F 由哪几行覆盖

| 场景 | 新顺序里的步骤 | 实测 |
| --- | --- | --- |
| A 冻结非空 build_sha | #10 build-complete，#11 get build_sha | 旧侧 `b3f813de...`（初始 commit），新侧 build:v1:git token，stdout 面 KNOWN（同一 commit 校验通过） |
| B verify-pass | #23 verify-pass，#24 get verify_result | 见下方「预先存在的问题」 |
| C verify-fail 回退 | #17 verify-fail，#18 get build_sha，#19 get verify_result | #18 两侧都是 `null`，#19 两侧都是 `fail`，#17 yaml 面 PASS（phase=build 逐字一致） |
| D 提交后重新冻结新 SHA | #20 commit 2，#21 build-complete，#22 get build_sha | 旧侧 `c2ce00b2...` 不等于 A 的 `b3f813de...`；新侧 token 的 revision 段与旧侧 SHA 校验同源（KNOWN） |
| E barrier 拒绝 | #14 commit 1，#15 verify-pass（首列期望 1），#16 get phase | 两侧 exit 都是 1（PASS），stderr 面 KNOWN（已登记的类型化 blocker 差异），新侧文案为 `verify-build-revision-untrusted reason=revision-stale`，#16 `get phase` 两侧都是 `verify` |
| F ship / archived | #25 ship-complete，#26 archived，#27 get archived | 见下方「预先存在的问题」 |

## 逐步核对（新旧两侧）

- 屏障判定依赖「冻结后 HEAD 变了」：第 1 轮 `commit 1` 之后 HEAD != A，所以 #15 在新侧被 `revision-stale` 拒；旧侧在 `agent_review_result` 处就先拒了（见下），exit 同为 1。
- seed 的 `verification_report` 与 set 的 `branch_status` 在 #12/#13 注入，verify-fail 不清它们（旧脚本 `state-transition.sh` 的 verify-fail 只写 `verify_result=fail` 与 `build_sha=null`），所以第 2 轮不用重新 seed。
- 两个 commit 的文件名、内容、日期都固定，父链 `initial -> c1 -> c2` 双侧一致，所以双侧 SHA 相同。
- 只有 #10 与 #21 两次成功进入 verify，所以 `max_rounds: 2` 下 #17 的 verify-fail 在第 1 轮，允许；#23 的 verify-pass 是前进边，不受回退上限约束。

## 预先存在的问题（未处理，供主线决定）

夹具头部写的 B「最终 verify-pass 成功」和 F「pass -> ship -> archive -> archived」其实早就不成立：旧脚本 verify-pass 在 barrier 之前先要 `agent_review_result=pass`（`state-transition.sh` 第 182 行），而夹具已删掉手填该字段的 set 步，所以旧侧一律拒绝；新侧要步骤声明的评审者跑过，也拒绝。现状（改前改后一样）是 #23 verify-pass、#25 ship-complete、#26 archived 两侧都被拒，靠 `.oracle-exit-divergences` 与 `.oracle-stderr-divergences` 登记为已知差异，`verify_result` 停在 `fail`，`get archived` 两侧是 `false`。这与上限变更无关，我没动它，也没有改头部 B 与 F 的描述（任务只让我改与顺序有关的句子）。同理 E 在旧侧也不是因 barrier 被拒，而是先撞 `agent_review_result`；exit 1 和 YAML 不变仍逐面比对，stderr 差异已登记。若要让 B/F 真正成功，需要另外设计（例如给新侧补评审者、给旧侧补手填字段的替代），超出本任务范围。
