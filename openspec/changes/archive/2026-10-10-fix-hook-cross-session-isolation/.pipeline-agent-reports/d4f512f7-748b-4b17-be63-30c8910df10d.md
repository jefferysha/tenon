## 设计取舍（给评审者）
- 认领：带会话 id 的解锁同时认领「自己的分文件」与「归属它的单文件」（单文件 `change=` 为空属于全部会话、`change=` 非空按本会话任务解析），不认领别的会话的分文件；否则单文件拦着本会话而本会话解不开，会死锁到 30 分钟过期。无会话 id 的 hook 只看单文件，碰不到任何分文件。
- 分文件里的 `session=` 与文件名不一致 → 对任何会话都无效（只靠 TTL 清理），不会被别的会话借用。
- 手动 acknowledge 检测只看命令文本：去引号 / 反斜杠（含续行），按 `& | ; ( ) ` { } < >` 与换行拆段，段首（跳过 `NAME=值`）是 tenon 入口，或是包装器 / 解释器 / 复合命令关键字（env sudo nohup command xargs find bash sh zsh node npx if then …，此时整段里找 tenon 入口），其后 review → acknowledge，且本段没有 `--delegated`（`#` 注释和 `--` 之后的不算）。已用例覆盖 `bash -c '…'`、`bash -lc "…"`、`env … tenon`、`env -u X tenon`、行首空白 / 制表符、`;` `&&` `||` `&` `|` 换行串接、`$(…)`、反引号、子 shell、`sudo`、绝对路径、`node …/tenon.mjs`、`npx`、`xargs`、`if … then`、引号拆词、续行、`# --delegated`、`-- --delegated`、`--delegated=false`；只是提到这几个词的 `rg` / `grep` / `git commit -m` / `echo` / 写文档正文放行。
