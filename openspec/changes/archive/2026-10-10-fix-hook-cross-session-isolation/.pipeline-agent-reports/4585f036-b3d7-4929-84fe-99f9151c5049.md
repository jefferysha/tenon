## 结论摘要
- 阻断线是 medium，有 1 条 medium 阻断项：`tenon review --as reviewer <acknowledge> x` 这类"选项夹在 review 与子命令之间"的写法能绕过手动确认拒绝。已用真实 hooks/gate.sh 复现，现有拦截表没有对应用例。
- 另有 4 条 low：花括号步长写法、误拦范围、包装器清单不全、一条 HEAD 既有的超时放行。
- 第三轮 security 的"词中拆分绕过"整体已修：引号、反斜杠、续行、$'…'、JSON \u、\x/八进制/\u/\U、普通花括号展开都能还原后判定。
- 判定本身没有崩溃类缺陷：把 gate.sh 第 141-578 行的 helper 段在 bash 3.2 + set -uo pipefail 下喂了 1500 个随机组合，没有任何 stderr 输出。

## hooks/gate.sh 本任务改动逐函数结论
- PIPELINE_MARK=\002：选择合理，还原函数都排除了 \0 \1 \2 \177。无问题。
- pipeline_strip_chars：read -a + 空 IFS 一次拼回，丢空片，末片 here-string 换行去掉；空输入返回空串；线性。无问题。
- pipeline_decode_json_ascii_escapes：held 状态机对三连反斜杠、末尾反斜杠、非 u00[0-7] 情形都能还原回去；00 01 02 7f 与 ≥0x80 不还原；\u000a 会还原为换行（失败关闭方向）。无问题。
- pipeline_restore_shell_escapes：x(2)/u(4)/U(8)/八进制(3) 位截取；count=0 与 0..2、>126 原样保留；还原字符前垫 MARK；\\x61 过拟合还原（失败关闭）；printf -v 的 hex 来自受控 %02x，无注入。无问题。
- pipeline_shell_unquote：续行整体去掉，其余反斜杠换 MARK，引号前的 $ 去掉；引号内空白会被当词分隔（见发现 3）；线性。无问题。
- pipeline_clean_marks：无 MARK 零成本。无问题。
- pipeline_text_may_spell_acknowledge：k/w/g 先排除，再 IFS=字母 read 逐字母切一次；here-string 换行保证不触发尾分隔符差异；线性，是"花括号拼出该词"的必要条件。无问题。
- pipeline_brace_find_group：最左有效组，${…} 跳过，深度 0 逗号，单字母序列正反向，步数 20000 返回 2；只认 {x,y} 和 {x..y}，{x..y..N} 步长未认（发现 2）。
- pipeline_brace_expand_word：迭代栈，顺序与 bash 一致，空串丢掉，上限 128。无问题。
- pipeline_expand_braces：按行/段/词切，词预算 200、单词 ≤256，超限置 OVERFLOW，字母能拼出才置 HIT；空数组用 ${arr[@]+…}，set -u 下安全；全局变量只用 _PIPELINE_BRACE_*。长压缩 JSON 载荷加 acknowledge 会按手动确认拦，可接受。
- pipeline_word_is_tenon_cli / pipeline_word_wraps_command：与 HEAD 语义一致；封闭名单，名单外启动器覆盖不到（发现 4）。
- pipeline_command_runs_manual_acknowledge：流程顺序正确；set -f/set +f 成对且所有 break 落在 set +f 之前，return 0 在 set -f 之外；IFS 为 local；"${segments[@]}" 在 set -u 下安全；raw/word 分离使标记词不算 --delegated，-- 与 # 之后也不算。缺陷：arm 状态机 review 与 acknowledge 之间不容忍带值选项（发现 1）。
- 调用点与 ACK_COMMAND_MAX：预筛键名集合覆盖 pipeline_json_get_command 读的全部键，不比判定窄；转义特征一律解码，其余用 may_spell；超限只做字面检查；拒绝提前到受保护路径之前；json-input.sh 缺失按文件总纲 exit 0 fail-open，helper 在同文件内无缺失问题。

### 线性性与性能抽查（本机 bash 3.2.57，整个 gate 墙钟）
- 密集 \x41 约 52K 字符：2.9 秒，放行（拆词确认，超出上限所致）。
- 换行填充 64K：2.8 秒，放行。分号填充 64K：1.5 秒，拦。反斜杠填充 60K：1.2 秒，放行。
- 花括号词 56K：0.3 秒，拦。& 填充：0.4 秒，拦。嵌套花括号：0.4 秒，拦。超限含字面 acknowledge：0.3 秒，拦。
- 判定函数自身没有平方级退化。builder 的"最坏 1.5 秒"在编码后约 64K 内成立；我用 json.dumps 构造的载荷编码后更长，部分越过上限。
- 观察：超过 64 KiB 且原文不含 acknowledge 的命令直接放行并进入 HEAD 既有受保护路径，'""'*40000+' echo done' 为 5.55 秒；含 bash 字样的 '""'*15000+' echo bash' 实测 84.65 秒（hooks/lib/protected-writes.sh 本任务未改，见发现 5）。
