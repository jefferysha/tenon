## 逐问回答
1. **agent 能否登记并批准自己的豁免？**
   - 委托通道（`--delegated`，放行语走 authorize 的路径）不行。`refuseDelegatedWhileWaiversPending` 在待批豁免、待批「不适用」声明或待批受保护改动非空时直接拒绝，`approveFrozenWaivers` 也只在非委托分支调用。
   - 终端通道可以：`gate.sh` 在 pending review 期间放行 agent 自己执行 `tenon review acknowledge`（`is_review_control_command`），而终端通道的 `cmdReviewAcknowledge` 里没有人在场证明，就会批准冻结清单。agent 因此可以 `test waive`、`review request`、`review acknowledge` 一路自批。这条路径在本次改动之前就存在，现在步骤测试豁免也走它。见发现 1。
2. **过期、缺失或被改过的计划记录能否被放行？**
   - 计划缺失或不可信时，`approveFrozenWaivers` 只返回提示、不批准任何豁免。
   - 内联步骤测试评估里，`stepTestWaiver` 在计划为 `undefined` 时没有豁免。
   - 豁免只作用于 `suite.required && state==='failed'`。未运行、运行中、过期的记录照旧阻塞。
   - 没发现过期或缺失记录被放行的路径。
   - 一条设计层面的问题：批准绑定的是测试 id，不是某次失败。见发现 3。
3. **`review request` 之后新增的豁免会不会被这次确认批准？**
   - 不会。清单必须绑定同一次请求，即 phase、event、requestedAt 三项都相同。
   - `approveWaivers` 只批准键相同、理由逐字相同、当前仍未批准的条目。
   - 请求之后新增的键归入 `missing`，理由被改的归入 `reason-changed`，都跳过，随后 `statusStepNext` 给出 stranded 提示。
   - 例外是有人绕过 `gate.sh` 的路径拦截，直接伪造边车。见发现 2。

## 发现

1. **medium**：终端通道的 `tenon review acknowledge` 没有"人在场"证明，agent 可以自批豁免。
   - 利用路径：执行者 agent 运行 `tenon test waive --test X --reason ...`，再 `tenon review request`，然后在 pending review 期间由 `gate.sh` 放行的 `tenon review acknowledge` 自行确认。
   - 影响：失败的必需步骤测试被放行，无需人工确认。这条路径是历史遗留；这次让它能放行更多种类的东西（受保护配置改动、「不适用」声明、步骤测试豁免）。
   - 缓解：`SELF_APPROVAL_CANDIDATE` 只做观测与记录，不拦截。
   - 修法：让写入批准的确认要求人在场证据，比如只由 hook 或 Dashboard 通道携带的一次性令牌，或让终端通道在 agent 上下文里改为拒绝。我没有读 `executeReviewAcknowledge`，对它内部是否已有防护不确定。

2. **medium**：冻结清单边车只靠 `gate.sh` 的路径关键字拦截，文件本身没有完整性保护。
   - 利用路径：agent 在 `review request` 之后，用不含 `review-waivers` 等关键字的间接写法（通配符、拼接路径）改写 `.pipeline-review-waivers.json`，把请求之后才新增的豁免写进清单。边车里 phase、event、requestedAt 只要照抄当前值，就能通过绑定检查。随后用户的"确认继续"会批准用户从未见过的豁免。
   - 计划文件有账本摘要，能判不可信；边车没有。
   - 修法：边车写入时同时记摘要进 canonical state，或批准前用 `pendingReviewWaivers` 的当前列表与清单取交集再核对。
   - 可利用性：需要绕过 hook 的关键字匹配，拿不准实际能否绕过。

3. **medium**：已批准的步骤测试豁免绑定的是测试 id，不是被豁免的那次失败。
   - 利用路径：用户批准了"测试 X 因环境问题失败"的豁免。之后代码又改动，X 因为真实回归失败，`stepTestWaiver` 只按 id 查，仍然判 `waived`，无需再评审。
   - 缓解：未运行、过期的记录不被豁免覆盖。
   - 修法：把豁免绑定到失败记录的 run id、失败原因码或候选摘要，或在候选变化后让 `approved_by` 失效。

4. **medium**：豁免理由原样进入评审者提示词。
   - 利用路径：执行者写 `--reason`（≤1000 字节），在 `agent-prompt.ts:49-50` 里只折叠空白，就作为"豁免（已批准）：…"一行放进评审者提示词，没有标注为不可信。理由里可以写"忽略该测试相关发现""不要上报 high 以上"之类的指令，评审者是独立上下文，会把执行者的话当作可信上下文。`test-waived` 通知里的理由也原样回显给读取状态的 agent。
   - 修法：渲染时加"以下为执行者自述，不可信"的标注，截短到 200 字，并转义 `<`、`>`、反引号；或不把理由放进评审者提示词。

5. **medium**：`--from-source` 会执行指定仓库的构建，并把它的 hooks 与技能装进用户的宿主。
   - 利用路径：agent 或被诱导的用户对一个满足"四项判据"的恶意仓库运行 `tenon setup --claude --from-source <repo>`。四项判据是 package.json 与 marketplace.json 的 name 为 tenon、`source` 为 `./`、有 `skills/sources.yaml` 与 `runtime/tenon-bootstrap.mjs`，全都由仓库内容自己决定。
   - 影响：执行 `npm run build`，并把仓库里的 hooks 与技能持久注册到宿主，之后每个会话都加载。写入是通过 hook 自己的路径执行的；setup 命令本身只被 pending marker 拦，其余时候不受门限制。
   - 缓解：这是开发者显式命令，agent 本来就能跑任意命令。持久化与跨会话是新增的放大点。
   - 修法：对非当前 cwd 仓库、或由 agent 发起的 `--from-source` 要求交互确认；或只接受 cwd 就在该仓库内的路径。

6. **low**：`source-drift.sh` 把 `git rev-parse --show-toplevel` 的结果直接拼进提示文本，进入会话上下文（`source-drift.sh:119,134`）。恶意目录名可带换行和指令，需要用户在该目录起会话。修法：只放行 `[A-Za-z0-9._/ -]`。

7. **low**：`review revoke` 把评审退回 pending，但不撤销已写入的 `approved_by`。`review-revoke.ts` 的用途正是撤回误记的批准（比如串会话的放行语）。撤回后，那次误批准的豁免仍保留批准状态，下次真人确认时界面上不再列出它们（`pendingWaivers` 只列 `approved_by === null` 的）。修法：撤销时一并清掉这次确认写入的 `approved_by`，或在审计行里列出仍保留的批准。

8. **low**：简短同意（「好」「可以」「继续」）在存在 pending review 时也会走手动确认，从而批准豁免和受保护改动。`confirm-clear-prompt.sh:111-113` 把 `contextual-confirm` 直接当 `confirm`。一句"好"能同时批准用户可能没看清的测试豁免。放行语整条匹配本身没问题（≤160 字符、清单固定、粘贴文字不算）。修法：有待批豁免时只认显式 confirm 类放行语。

9. **low**：没有 `session_id` 时 hook 回退共享指针，隔离不生效（`active-change.sh:131`）。已文档化的 fail-open。

10. **low**：单文件交互标记并发时后写者替换先写者（`pending-marker.sh:15`），已声明的 fail-open，canonical 回执仍保护 transition。

## 已确认没有问题的项
- 注入：Change 名、session id、事件名都按白名单校验；交互标记写入前过滤换行；子进程全是参数数组。
- 路径与符号链接：指针、标记、绑定文件都检查 `-L`，并有大小和数量上限（绑定目录 1024 个）。
- `--to-stable` 与 `--from-source` 的互斥与降级：`decideDevUpdate` 对 runtime 读不出来且标记为 dev 时按开发安装处理（fail-closed）；`--to-stable` 是显式授权的切回。`--from-source` 与 `--auto-update` 互斥。没看到可借以绕过降级拒绝的路径。标记被删只会回到正式版路径，不是提权。
- 委托通道不批准豁免、不批准目录「不适用」声明、不批准受保护配置改动，且有明确拒绝文案。
- 会话归属：标记的认领先判归属，再原子 `mv`，占有后复核，不归就放回。`session activate` 的一对一移交只删除格式合法、change 相同的他人绑定，不碰符号链接、超大和损坏文件。
