## 发现清单

1. **low**，`hooks/pending-marker.sh:15`、`hooks/gate.sh:441-456`（新）
   - 问题：按会话分文件后，只有本会话自己调用 `fresh` 才会清掉过期的 `.pipeline-pending-interaction.<sid>`。未绑定 Change 的会话或已结束会话留下的分文件永远不清，只有 `task-delete` 按绑定清。它们不拦截任何人，只是残留，已被 `.gitignore:28` 和指纹排除覆盖。
   - 修法：`doctor` 的 `project:markers` 提示这类过期分文件，或 `session-start.sh` 顺手清理超过 TTL 的分文件。

2. **low**，`packages/dashboard-app/src/workspace/stageTests.ts:40`（新）
   - 问题：`stageTestCount` 只数 `status === 'passed'` 的行，已批准豁免（`waiver === 'waived'`）的测试在「n/m」计数里不算完成，而行内的状态药丸已显示完成。纯展示不一致，不影响门禁。
   - 修法：计数里把 `waiver === 'waived'` 也算进去。

3. **low**，`hooks/source-drift.sh:55`（上轮 4，未修）：换行文件名在 shell 端被拆成两行；应遇到含换行路径就整条提示不输出。

4. **low**，`hooks/active-change.sh:66`、`hooks/active-change.sh:90`（上轮 6，未修）：绑定超过 1024 个后本会话被静默判为无任务；应在 `doctor` 里警告并清理过期绑定。

5. **low**，`packages/cli/src/commands/setupHost.ts:279-280`（新）：同一行注释「正式安装成功：开发标记不再代表现状……」重复了两行；删掉一行。

6. **low（已知推迟）**，`hooks/gate.sh:237-244`：手动 acknowledge 的拦截先对原始 JSON 做 `*acknowledge*` 子串预筛，再对解码后的命令做静态判定。JSON 的 `\u` 转义、变量拼命令名、脚本内调用可绕过。属于用户已决定的「命令文本静态判定」，真正边界在 CLI 与 server 对「人在场」的要求。

7. **low（已知推迟）**，`packages/cli/src/commands/review-revoke.ts:104`：`review revoke` 只把回执撤回为 pending，不撤回已写入的豁免批准；`statusStepExits.ts:53-70` 已向用户说明该限制。

8. **low（已知推迟）**：简短同意在有待批准豁免时仍会批准它们（`confirm-clear-prompt.sh:187`）；statusline 只认单个交互标记文件。

### review-ack.sh 写入链路（读全文）

- **会话校验**：`pipeline_acknowledge_active_review`（:105-122）先读 `.pipeline-pending-review` 的 `change`，再经 `pipeline_review_active_change_name` → `pipeline_session_change_dir` 取本会话任务，两者必须相等才继续。别的会话的确认永远不会确认本会话的评审，也不会让「无绑定的恢复会话」确认。
- **失败路径**：所有失败（标记不存在、标记不合规、本会话无任务、两者不一致、没有 `tenon`、模式非法、CLI 非零退出）都返回 1，不写任何状态，不删标记；调用方 `confirm-clear-prompt.sh:184-196` 只在返回 0 且 `REVIEW_CHANGE` 非空时才宣告「评审已确认」，有对应用例（见下）。
- **delegated 模式**：额外校验会话 id 字符集和 128 位上限，并通过 `TENON_HOST_SESSION_ID` 传给 CLI，由 CLI 对照持续授权；manual 模式不带会话 id。
- **标记解析**：拒绝符号链接，只认 `pipeline-review-v2` 首行，change 名字符集限制为 `[A-Za-z0-9_-]`，事件名同样限制，不会把畸形值回显进 agent 上下文。
- 一个观察（不是发现）：`command tenon` 走 PATH，PATH 被篡改时会调用别的可执行文件。这是整个 hook 体系已有的信任假设，本次未引入。
