## 新增用例

1. `计划被篡改（tampered）：即使输入里带着已批准的豁免也不读，失败仍是 test-failed，没有 test-waived 提示`（kernel）
   - 对两种 tampered 输入各断言一次：真实形态 `{ state: 'tampered', reason }`（类型 `PlanInput` 的 tampered 分支本就不带计划内容），以及把已批准的 `test:unit` 豁免计划硬挂在输入上的形态（`as unknown as` 转型，证明是否读豁免只看 `state`，不看内容在不在）。
   - 断言：`codes` 恰为 `['test-plan-tampered', 'test-failed']`；`blockers[1]` 是 `test-failed`、subject `step:unit`、fix `tenon test run demo unit`；`pass === false`；verdict 为 `state: 'failed'`、`detail: 'exit-code'`；`notices` 为空（没有 `test-waived`）。
2. `豁免理由含换行、制表符与连续空格：折成单个空格、首尾去空白，豁免仍只占一行，不多出原始换行带来的行`（CLI）
   - 理由为 `'  第一行\n  第二行\t\t第三行\r\n\n'`。
   - 断言：含「豁免」的行恰好一条且等于 `  豁免（待评审批准）：第一行 第二行 第三行`；它紧跟在 `- size 未通过 …` 之后，下一行是 `- lint 通过 …`；整份提示词逐行等于理由本来就是单行 `第一行 第二行 第三行` 时的渲染；没有只含「第二行」而不含「第一行」的行。
