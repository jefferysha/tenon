## 新发现（补齐中新增，均为 low）

- **N1** `hooks/source-drift.sh:75`：路径经 `tr '\0' '\n'` 后按行读，仓库内文件名含换行时与 TS 侧口径不一致。TS 侧遇到这种路径会抛错，shell 侧会得到错误的摘要，表现为误报漂移。fail-open，不影响安全。修法：与 TS 侧一致，发现换行路径就整条不提示。
- **N2** `packages/kernel/src/test-system/plan.ts:155` 与 `review-waivers.ts` 的 `decodeWaiver`：`approved_candidate` 和清单里的 `candidate` 都要求是 `workspace:sha256:` 工作区指纹。失败记录绑定的是 `git:` 或 `sha256:` 候选时，批准写不进去，豁免会一直是待批准。我没找到能触发的真实路径，只是类型口径比 `stepTestWaiver` 的比较窄。不确定点：非 git 工作区是否会产生这种候选。修法：确认候选来源后统一口径，或在冻结时拒绝并提示。
- **N3** `packages/cli/src/commands/review-acknowledge.ts:125`：AFK 只通过 `deps.env?.('TENON_AFK') === '1'` 判断。`deps.env` 缺省时不会触发拒绝。真实装配里 `env` 总在，我没找到未装配的真实路径。修法：`env` 缺席时按失败关闭处理，或把 AFK 判定收进一个必选函数。
- **N4** `packages/cli/src/commands/review-revoke.ts:96`：审计写用 `deps.history?.append`，`history` 缺省时静默跳过，与注释"审计写不进去就抛错"不符。真实装配里 `history` 总在，仅影响测试装配。修法：缺省时抛错。
- **N5** `packages/cli/src/commands/setupHost.ts`（`clearDevInstallMarker` 调用上方）：同一条注释重复了两行，纯整洁问题。修法：删一行。
- **N6** `.gitignore`：新增 `.claude/` 会让项目级 `.claude/` 目录里新增的文件不再被 `git status` 看到。已跟踪的文件不受影响，但今后在项目里共享 `.claude/settings.json` 之类的文件会被悄悄忽略。修法：确认是否有意；若只想忽略本机生成物，改成具体路径。
