## 依赖方向和接缝

没有发现反向依赖或环，三个重点问题的结论如下。

1. **内核提交后直接删评审标记，不算分层泄漏。**
   - 全部回调（`deps.breadcrumb`、`deps.history`、`deps.interaction`）在 `transition-application.ts` 里确实是端口。
   - 但同一文件已经直接从 `../state/index.js` 调 `readCurrentRunRevision`、`applyBreadcrumbTail`、`clearReviewGatePatch`。这个 `state` 模块在内核内部，本来就带文件系统读写，所以 `clearReviewMarkerOfChange` 与既有写法一致。
   - 标记清除放在 `transition-application.ts:250-256`，在提交之后，失败只告警，也符合 breadcrumb 和 history 的投影写入惯例。
   - 设计里「不新开端口」的决策站得住：两个宿主给的是同一个实现，没有第二个适配器，端口只会是假接缝。
   - 唯一的不对称是 `acknowledge` 路径仍走注入的 `clearReviewMarker` 回调（`packages/cli/src/main.ts:249`、`packages/server/src/serverPostDecisionRoutes.ts:275`），而转换路径是内核直调。见 low 级发现。
2. **`backEdgeRounds` 和 CLI `next` 的判定部分重复，缺共用谓词。**
   - 内核按「非放弃事件、非前进边、`isRoundsLimited`、`rounds !== null`、`!roundsExhausted`」判 `within-budget`。
   - CLI 在 `statusStepExits.ts` 的 `roundsRemain` 加 `gatedBackActions` / `exitActions` 里，再用「是评审门、唯一回退边、非放弃、轮次未用完」重写了一遍。
   - 两边共用的原语只有 `roundsExhausted`、`isAbandonEvent`、`rounds === null` 当作未知。
   - 区别是 CLI 靠 `rounds` 入参隐含「受约束步骤」，内核显式调 `isRoundsLimited`。这个隐含靠 `statusStepNext.ts` 里 `rounds` 的注释保证。
   - 它们现在是一致的，但「免回执」这条规则一旦变化，要两边同步改，CLI 的单测也不会因内核变化而失败。
   - 建议在内核导出一个纯谓词（例如 `backEdgeWaivesReview(plan, from, to, event, rounds)`），CLI 复用它。这不阻断放行。
3. **`hooks/lib/read-only-command.sh` 与 `gate.sh` 的边界基本清晰。**
   - 接口只有 `pipeline_command_is_read_only`，不掺自审批判定。
   - `gate.sh` 里自审批检查排在只读放行之前，边界处理得对。
   - 库缺失时降级为恒返回 1，失败关闭，并且是惰性加载。

## 发现清单

- **medium**，`packages/cli/src/commands/statusStepExits.ts:31-52, 129-136` 对照 `packages/kernel/src/workflow/transition-rounds-gate.ts:36-48`：「轮次内回退边免评审回执」这条规则在内核和 CLI 各写了一遍。建议把规则抽成内核的纯谓词，CLI `next` 和内核转换共用。现状两边行为一致，风险是以后单边漂移。不确定：CLI 靠 `rounds` 入参隐含「受约束步骤」，抽谓词时要确认 CLI 传入的 plan 信息够用。
- **low**，`packages/kernel/src/workflow/transition-application.ts:250-256`：标记清除在转换路径是内核直调，在 `acknowledge` 路径是宿主注入的 `clearReviewMarker` 回调，同一个标记有两种清法。当前可接受，建议加注释说明两条路径刻意不同的原因。
- **low**，`hooks/gate.sh:614`：`pipeline_command_has_shell_metachars` 现在只剩 `is_review_control_command` 在用，注释还在解释它「不再用于此」，属于历史说明，会随时间失真。建议改写成不依赖旧函数的表述。
- **low**，`hooks/lib/read-only-command.sh:1-10`：建议在库头部注释里点明「控制面放行（`tenon transition` 等）不在此库」，免得以后有人把 transition 加进只读名单。

## 残余风险

- `packages/cli/dist/tenon.mjs` 和 `packages/server/dist/dashboard.mjs` 是产物，按要求没审。
- `gate.sh` 里 `tenon transition` 的放行依赖 CLI 兜底：CLI 必须拒绝没有已批准回执的前进边和轮次用完后的回退边。该兜底由内核 `backEdgeRounds` 的 `exhausted` 分支和回执检查保证，这次只读了代码，没有跑测试验证。
