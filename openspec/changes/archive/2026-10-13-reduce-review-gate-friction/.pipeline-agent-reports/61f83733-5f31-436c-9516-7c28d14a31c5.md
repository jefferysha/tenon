## 覆盖摘要

**审了什么**：交付面共 24 个源文件和测试。dist 产物与 `openspec/changes/` 下的状态文件按要求忽略。

- kernel：`transition-rounds-gate.ts`、`transition-application.ts`、`transition-application-types.ts`，以及新增调用的 `clearReviewMarkerOfChange`（`state/markers.ts`）。
- CLI：`transition.ts`、`statusStepExits.ts`、`statusStepNext.ts`、`statusStepRoundsRoute.ts`。
- server：`transitionResult.ts`，另读了 `server/src/transition.ts` 的接线。
- hooks：`hooks/gate.sh`（完整读了 `is_review_control_command`、`pipeline_transition_command_ok`、`gate_check_marker`、读库加载）、`hooks/lib/read-only-command.sh`（全文逐行读）。
- 工具：`tools/verify-skills.sh`、`tools/generate-product-identity.mjs`。
- 测试：`tools/test-hooks.sh` 与各 `*.test.ts` 只做存在性检查，没有逐条读。

**动态实验**：写了约 55 条对抗用例到临时目录，用 `bash` 和 macOS `/bin/bash`（3.2）各跑一遍，两边结果一致。覆盖：

- 引号拼接绕过：`--p"re"`、`-ex\ec`。
- 重定向：`>/dev/null` 剥离与后续写入组合。
- 后台执行与管道：`&`、`|&`。
- 展开：`$"…"`、`$` 结尾、`~`、glob。
- 转义：反斜杠转义的分隔符。
- 其他：`sed -n` 选项重排、`file -bC`、`find -fprintf/-ok/-exec +`、`git log --out`、`test -v "a[$(…)]"`。

没有找到「判只读却能写文件或执行程序」的路径。

**不是危险路径的几处**：

- `ls ;;` 和 `ls \` 被判只读，但在 bash 里是语法错误，不执行。
- `ls *`、`ls ~`、`ls $"x"` 被判只读，它们只是展开，不执行也不写。

**未覆盖**：

- 没有运行 `tools/test-hooks.sh` 和 TS 测试套件。两者可能写仓库或临时文件，而评审要求工作区零变化。
- `tenon get`、`tenon inbox`、`tenon status` 是否真的无副作用，属于改动前就在名单里的行为，没有重审。

**结论要点**：

- `transition-application.ts` 里，轮次读取和回执判定在同一把 Change 锁内，读的是同一份 `tx.state`。
- `roundsOf` 缺席或返回 null 时失败关闭（照旧要回执）。
- 放弃边和前进边永远不走 `within-budget`。
- 标记清除在 `tx.commit` 之后，失败只往 `warnings` 里追加，不影响 `applied` 结果。
- CLI 的 `switch` 和 server 的 `mapTransitionResult` 都补了 `review-marker` 分支，告警渲染完整。
- `gate.sh` 的读库缺失会定义一个恒返回 1 的占位函数，失败关闭。`verify-skills.sh` 和 `test-hooks.sh` 的红线也覆盖了缺失情形。
- `pipeline_transition_command_ok` 只放行字符集 `[A-Za-z0-9_ -]`，且恰好两个非 `-` 开头的位置参数。多余参数、制表符、引号都会被拒。
- 自审批拦截排在只读放行之前，只读组合管道里嵌入 Dashboard 访问也会被拦，顺序正确。
- `set -u` 下的数组用法都有长度守卫，bash 3.2 下实测无报错。

## 发现清单

1. **low**，`hooks/gate.sh:596-598`：评审标记下放行的 `tenon transition <change> <event>` 没有绑定到标记所属的 change。`pipeline_review_marker_change` 已能取到标记的任务名。
   - 修法：比对 `<change>` 与标记任务名，不一致就不放行。
   - 当前风险有限：前进边和放弃边仍由 CLI 要回执，别的任务的转换也不受本任务的评审状态约束。这样做只是把「恰好一种形态」收紧到「恰好本任务」。
2. **low**，`hooks/gate.sh:538`：`[!A-Za-z0-9_\ -]` 的范围在部分 locale 下（bash 3.2 的 en_US 系）按排序规则解释，可能放进非 ASCII 字母。
   - 修法：在该函数内用 `LC_ALL=C` 的子判断，或把范围换成显式 POSIX 类 `[[:alnum:]_ -]` 并配合 `LC_ALL=C`。
   - 后果仅限多放行一个会被 CLI 拒绝的参数名，不构成越权。
   - 主线注：`hooks/gate.sh` 文件开头已设 `LC_ALL=C`，该范围按字节解释。
3. **low**，`hooks/lib/read-only-command.sh:77-102`：名单里有两类命令会拉起外部程序，不是写文件，但不是纯读。
   - `rg -z` 会调用 gzip/xz 等解压程序。
   - `git diff` / `git log` / `git show` 在仓库配置了 `diff.external` 或 textconv 时会执行该程序，例如 `git diff --ext-diff`。
   - 这需要先写配置才能利用，改动前也是如此。可以考虑把 `--ext-diff`、`--textconv`、`-z` 加进拒绝名单，把「只读」收得更严。
4. **low**，`packages/cli/src/commands/transition.ts:236` 与 `packages/server/src/transitionResult.ts:47`：`review-marker` 告警的渲染文案在两处重复。
   - 内核层只有「产生告警」的单测，CLI 和 server 的渲染分支都没有用例，将来改文案容易两边不一致。
   - 修法：补一条清除失败的集成用例，断言 stderr 含该 WARN。
5. **low**，`packages/kernel/src/workflow/transition-application.ts:252-256`：`clearReviewMarkerOfChange` 的 `readFile` 遇到非 ENOENT 错误（如标记路径被目录占用）会进告警分支。这符合设计。
   - 注释写「30 分钟后失效」依赖 `gate.sh` 里 review 标记 TTL 为 1800 秒，两处是硬编码。
   - 修法：从同一常量引用，或在注释里点明依赖，避免 TTL 调整后提示失真。

## 残余风险

- 只读判定是文本解析，不是语义解析，靠失败关闭兜底：任何新增的 shell 语法特性或名单内命令的新写入选项都会成为新的绕过面。每次扩名单都要补对抗用例，尤其是参数可执行或可写类选项。
- 本任务标记是项目级单文件，清除只认任务名。同一任务在两个会话里并发转换时，先成功的一方会清掉标记。这是预期行为，但没有测试固化。
- 轮次免回执依赖 `roundsOf` 的接线。CLI 和 server 都已接线，以后新增宿主若漏接，会退回要回执的老路径，只是多一次确认，不会放宽权限。
- 没有跑 `tools/test-hooks.sh` 和 TS 测试套件，所以「测试全绿」没有独立核验。需要主线或 CI 的 verify job 去确认。
