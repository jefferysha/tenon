## 逐项结论

- **命令与参数注入：未发现。** `execFile` 和 `spawn` 都用数组传参，不经 shell；HEAD 先用 `isCommitId` 限定为 40 或 64 位十六进制，再拼进 `from..to`，不会被当成选项；日志命令末尾带 `--`；送进 `cat-file --batch` 的路径已被 `isObservedPath` 过滤掉控制字符和换行，不能借换行伪造多条查询；`status` 用 `-c core.fsmonitor=false` 关掉仓库配置里的外部命令执行。
- **路径穿越：未发现。** `required-output` 校验拒绝绝对路径、盘符、反斜杠、`..`、空段、控制字符，只允许 `{change}` 占位；模式按段匹配，不编译成正则，没有回溯风险；`document read` 先做词法折算，越出项目就拒绝，再由 kernel 核对它必须是本步的交接输入；退化遍历用 `lstat` 和 `realpath` 检查起点，目录项的 `isDirectory()` 对符号链接为假，不会跟进链接；`workingFileSha` 用 `O_NOFOLLOW | O_NONBLOCK` 打开并确认是普通文件，符号链接只读链接目标字符串。
- **反序列化与拒绝服务：未发现。** 账本读取有 4 MiB 上限、只允许普通文件；访问 512、产出 2000、读取 4000、路径长度 1024 都有上限；`JSON.parse` 后逐字段校验，不涉及动态求值；git 子进程有 20 秒超时和 64 MiB 缓冲上限，改动路径超过 2 万降级为 truncated；退化遍历有 `SCAN_ENTRY_LIMIT`。
- **本地 API 泄露：未发现。** `stepIo` 只返回相对项目根的路径、变更类型和技能名，没有摘要、访问 id、正文或绝对路径；已结束任务的路径经过 `archivedDocumentPath` 重映射；账本损坏时降级为空视图，错误里没有文件内容。

## 发现

- **low**（`step-checkpoint.ts:129`、`step-outputs.ts:296-327`）：纵深防御的小缺口，没有可利用路径。退化遍历的 `exact` 分支只用 `lstat` 加 `isObservedPath`，没有做 `realpath` 包含检查；因为 `isFile()` 对符号链接为假，目前是安全的，但以后改成 `stat` 就会出问题。修法：给 `exact` 分支也加上与非 exact 分支相同的 `realpath` 包含检查。
- **low**（`step-checkpoint.ts:upstreamRefs`）：`refs/remotes/origin/HEAD` 和 `@{upstream}` 来自仓库配置，只作为 `--not` 的 ref 参数传入，不执行任何东西，只是信任本地 git 配置，没有可利用路径。

## 残余风险

- 观察依赖本地 git 的输出。恶意仓库配置（如 hook 或 `core.*`）理论上能影响 git 命令，但已关掉 fsmonitor，且所有命令只读。
- 账本和任务目录与本地用户同权限，能写这些文件的人本来就能改状态，不构成新的边界。
- 没有逐行读 `workflowOrchestration.ts`、`serverGetRoutes.ts`、`contextBundleObservedPreview.ts`，这三个文件的结论只基于 `stepIo.ts` 的返回形状和 diff 统计。
