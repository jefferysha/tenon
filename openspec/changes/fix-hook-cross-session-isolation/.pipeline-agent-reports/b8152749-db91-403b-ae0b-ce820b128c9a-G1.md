### 状态面兼容（给主线重点看）

`max_rounds` 是真进 `FIELD_ORDER` 的字段，而 canonical 状态有「FIELD_ORDER 闭集」校验、YAML 投影有字节比对、评审绑定摘要是整份序列化状态的哈希（`reviewGateDecisionStateDigest`）。如果空值也写出一行，本仓所有在途任务升级后都会被判成投影漂移，所有挂起的评审绑定都会失效。所以做成「空值不上 wire、不上 YAML」：

- `serializePipeline` 与 `withoutCompanionFields`：值为空串时省略 `max_rounds`；
- `canonicalState`：缺这个键读成空串（不算闭集违例）；`isPreciseLegacyFieldProjection` 同理；
- 结果：没设置过 `max_rounds` 的任务，wire / YAML / 摘要逐字节不变；只有设置了值的任务才出现这个键。

代价（已知限制）：设置过 `max_rounds` 的任务，N-1（升级前发布）运行时读 canonical 会因闭集校验失败而读不了。F6 里对本任务执行 `tenon set … max_rounds 1` 之后，本任务只能由源码版 / 新版运行时读，已装的发布版读不了。
