## 接口约定

### 前缀与版本

- 所有接口统一使用 `/api/v1` 前缀；不兼容的变更新增 `/api/v2`，禁止在 `/api/v1` 下改变已有字段的含义或类型。
- 资源路径用复数名词、kebab-case（如 `/api/v1/order-items/{id}`），动作用 HTTP 方法表达：查询 `GET`、新建 `POST`、整体更新 `PUT`、部分更新 `PATCH`、删除 `DELETE`。
- 请求与响应字段统一 camelCase；时间字段使用带时区的 ISO 8601 字符串。

### 统一响应

- 返回格式统一为：

```json
{ "code": 0, "msg": "success", "data": {} }
```

- 成功与失败都返回该结构；`code` 为 `0` 表示成功，失败时 `data` 为 `null`（参数校验失败除外，见错误码）。
- HTTP 状态码表达协议层结果（参数错误 400、未认证 401、无权限 403、不存在 404、并发冲突 409、服务端错误 500），`code` 表达业务结果。

### 分页

- 分页数据返回格式：

```json
{ "code": 0, "msg": "success", "data": { "page": 1, "pageSize": 20, "total": 0, "items": [] } }
```

- 请求参数 `page` 从 1 开始，`pageSize` 默认 20、上限 100；排序参数写作 `sort=createdAt,desc`。
- 列表为空时返回 `"items": []`，禁止返回 `null`。

### 错误码

- `code` 为 int，`total` 为 long；成功码与错误码表在后端统一定义，前端请求拦截器按同一张表处理。
- 错误码按范围划分：

| 范围 | 含义 |
| --- | --- |
| `0` | 成功 |
| `1000`–`1999` | 通用错误：参数校验失败、未认证、无权限、资源不存在、并发冲突 |
| `2000` 起 | 按业务模块分段，每个模块预留 1000 个码 |

- 参数校验失败时 `data` 返回字段错误列表：`[{ "field": "email", "msg": "格式不正确" }]`。
- 错误码一经发布不得改变含义；`msg` 面向用户可读，禁止返回堆栈、SQL 或内部异常信息。
