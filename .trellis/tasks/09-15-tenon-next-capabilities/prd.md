# Tenon 下一阶段能力设计

## Goal

让 Tenon 能支撑团队用 Claude Code / Codex 做真实前后端开发：评审由可配置的多个 agent 完成，测试有真实登记，
新项目带团队的开发规范，多人协作时知道谁做了什么，任务能在 Dashboard 删除和归档，工作流的输入输出看得懂、
自定义工作流也能真实接入 OpenSpec。

## Source Requirements（用户 2026-09-15）

1. 评审阶段可定义串行和并行的 agent，角色可以不同，通过渐进式披露加载需要的技能；评审角度包括架构、前端质量、
   后端质量、代码行数以及开发过程中需要审查的任何角度。
2. 每一步除了文档产物的变更和登记外，前后端开发中的测试也要登记：每一步的测试、回归、基准、前端 Playwright、e2e 等。
3. 每个项目的 AGENTS.md / CLAUDE.md 支持自定义，提供前后端标准模板（不同语言不同模板）；面向**任何新创建的项目**，
   不是 tenon-local 本身。新建项目时可以选择模板；UI 上能创建、预览、修改、删除模板；能选择写给 Claude（CLAUDE.md）
   还是其他 agent（AGENTS.md），可多选；必须真实起作用。基准模板的 15 条要求见子任务 `09-15-instruction-templates`。
4. 支持不同用户之间协作，参考 Trellis 的团队协作方式和获取用户 id 的方式。
5. 去掉当前创建的任务（已完成，见下）；并且 UI 要支持任务的删除和归档，真实起作用。
6. 工作流输入输出的优化方案已认可；创建工作流时应能选择是否接入 OpenSpec。
7. 支持自定义 agent，用于工作流每一个环节的评审或执行。agent 与 AGENTS.md 不是一回事：AGENTS.md / CLAUDE.md 是指令文件，
   属于项目级和用户级（按各宿主真实加载规则，编辑为 Markdown，UI 支持编辑、预览、应用、删除）；agent 是任务级。

## Cross-Child Constraints

- Dashboard 不调用模型：评审 agent、测试都由宿主（Claude Code / Codex）或 Tenon CLI 执行，Dashboard 只定义、查看、确认。
- 工作流 YAML 是唯一可编辑真相，工作流全局存储；新增的评审者、测试、OpenSpec 接入都要能在 YAML 里表达并在 UI 编辑。
- 门禁只有「评审」和「自动」两种语义。
- UI 用词：同一概念只用一个词，页面除错误信息外不写句子，任何地方不换行。
- 最小范围：只做明确需要的，不保留无人使用的旧能力。

## Key Decisions

- 2026-09-15 用户授权：后续决定全部按推荐执行，不再询问；能并发的工作全部并发执行。据此确定：UI「归档」保留、工作流最后一步界面改称
  「完结」；OpenSpec 接入允许只选部分文档（链路缺口只警告）；上游 skill 更新不需确认，只取清单内仓库并记录提交与哈希、显示变化。

- 2026-09-15 用户身份：默认 `git config user.email`，本机可覆盖（环境变量 → 本机配置文件 → git 配置），不做登录，
  记录标注为自报身份。评审、测试、任务负责人、模板、删除归档的「操作人」统一使用它。
- 2026-09-15 测试执行：由 Tenon 执行并登记真实结果；测试记录在项目根目录下按用户维护；测试方向在 UI 可配置，
  每个测试项的输入和输出都要登记。
- 2026-09-15 评审者：任何步骤都能挂，离开步骤前执行，与人工评审门独立可叠加；确定性检查（如代码规模）做成测试方向，
  评审者读取结果。
- 2026-09-15 agent 库：独立的全局 agent 库（每个 agent 一个 Markdown 文件），工作流按名称引用，任务开始时锁定；
  由插件维护，安装或更新插件时自动把内置 agent 写入全局 Tenon 目录，内置只读可复制。
- 2026-09-15 指令模板：与 agent 库相同，内置模板由插件维护并自动写入全局 Tenon 目录，用户模板并列存放；内置模板覆盖所有主流语言。
- 2026-09-15 前端设计：动画必须参考 GSAP 官方开源 skill；UI 组件参考 React Bits 等流行开源组件库；前端作业必须有项目全局
  `DESIGN.md`——它是整个项目的完整设计体系（图标、颜色、字体、组件、动效、个性化等所有细节，参考 hue 产出）；默认由「设计体系」
  任务作为项目前置条件产出，普通任务在规格步骤提变更、交付合并；产出与检查时机可按工作流 / 轨道自定义（如产品轨道在 build 定义）。
- 2026-09-15 技能来源：Tenon 调用的第三方 skill 全部从上游来源安装最新版本，安装和每次更新 Tenon 时同步更新，不再维护截断的
  第一方副本（子任务 `09-15-upstream-skills`）。
- 2026-09-15 第三方精简改写全部删除，直接用开源 skill；找不到明确上游的 skill 先删除；不自动配置 MCP，遇到需要再查。
- 2026-09-15 Tenon 自有 skill 只保留一个按工作流数据执行的 `tenon`，阶段 skill、simple-task、learn-record、tenon-researcher 删除，
  轨道差异写进工作流数据（子任务 `09-15-data-driven-runner`）。
- 2026-09-15 上游 skill 安装：Tenon 自己从 GitHub 拉取最新版本到可信技能目录，记录提交与哈希，不用 `npx skills`，不写宿主全局技能目录。
- 2026-09-15 版本号：Tenon 不够成熟，版本从 0.1.x 开始（子任务 `09-15-version-reset`）；v0.1.0 发布验收后删除全部 1.x 的
  Release 与标签。
- 2026-09-15 新建项目：Dashboard 支持选已有目录接入，也支持新建空项目（创建目录、`git init`、生成指令文件与目录骨架）。
- 2026-09-15 agent 与指令文件分开：agent 是任务级（执行或评审）；AGENTS.md / CLAUDE.md 是项目级和用户级指令文件，
  按各宿主真实加载规则（多数宿主两级叠加生效）管理，UI 用 Markdown 编辑、预览、应用、删除。
- 2026-09-15 归档：任何阶段的任务都可归档；归档是 UI 不再显示任务及其执行记录，不物理删除（参考 Codex），
  提供「已归档」入口可重新显示；删除才是物理移除。归档只对归档的人生效（个人状态）。删除只动工作区，不自动提交。
- 2026-09-15 任务区分用户：任务有创建者与负责人，工作台显示当前用户、任务负责人，并可按用户筛选；只有负责人能推进，
  其他人先「接手」。
