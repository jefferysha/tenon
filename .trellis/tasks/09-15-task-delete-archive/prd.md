# 任务删除与归档

## Goal

工作台可以直接删除或归档任务，操作真实生效并与 CLI 一致：删除是物理移除；归档是让任务及其执行记录不再显示，
数据全部保留，并有入口重新显示。

## Background (confirmed, see `research/current-lifecycle.md`)

- CLI 与 server 都没有删除任务的能力；`tenon --help` 只有 AFK `cancel`。
- 工作流最后一步「归档」做的是 OpenSpec 归档：`tenon transition <change> archived`（要求 phase=archive）+
  `openspec archive <change> --skip-specs --yes`，会把任务目录移动到 `openspec/changes/archive/`
  （`skills/tenon-archive/SKILL.md:95,107`）。
- Dashboard 工作台只有「含已归档」筛选（`dashboard-app/src/workspace/TaskListPane.tsx:72-76`），没有删除、归档操作；
  server 只有创建任务 `POST /api/changes`（`server/src/serverPostChangesRoutes.ts:143`）。
- 参考 Codex：归档会话是把会话记录从 `~/.codex/sessions/` 移到 `~/.codex/archived_sessions/`，列表中不再显示，
  文件保留，可以取消归档恢复（本机可见 `archived_sessions/` 目录）。

## Key Decisions

- 2026-09-15 用户确认：未走完流程的任务也可以归档，归档时记录停在哪个阶段。
- 2026-09-15 用户确认：归档是在 UI 上不再显示该任务及其执行记录，不是物理删除，也不移动任务文件（参考 Codex）；
  必须提供重新显示的入口。
- 删除是物理移除，与归档分开。
- 2026-09-15 用户确认：归档只对归档的人生效（个人视图，像 Codex），归档状态存在该用户自己的目录下，不影响其他用户，不需要提交同步。

## Requirements

- R1 工作台任务卡与任务详情提供「删除」「归档」操作，二次确认后执行。
- R2 删除：移除任务目录及其 Tenon 状态，清理引用它的活跃指针、评审标记、交互标记、AFK 队列项；刷新与 `tenon list` 都不再出现。
  只从工作区删除，不自动生成 git 提交（2026-09-15 用户确认）；删除后工作台提示有多少个未提交的删除，由用户自行提交。
- R3 归档：对当前用户而言，任务、步骤、文档、测试、agent 记录在工作台与相关列表中不再显示；其他用户照常可见；
  磁盘上的任务目录与记录保持不变；在当前用户的个人状态中记录归档时间、归档时所在阶段。
- R4 已归档入口：工作台提供「已归档」视图，列出已归档任务（名称、归档时阶段、归档时间、归档人），可查看详情，
  可取消归档；取消归档后任务回到原列表并保持原有阶段与记录。
- R5 已归档任务不接受推进操作（转移、评审、测试执行）；宿主中对其执行 Tenon 命令时提示先取消归档。
- R6 CLI 提供同等命令（删除、归档、取消归档、列出已归档），Dashboard 调用同一实现；操作写入审计记录（含操作人）。
- R7 正在执行中的任务（有待确认评审、AFK 运行中、宿主会话活跃）执行删除或归档时给出明确阻止或确认。

## Acceptance Criteria

- [ ] 在工作台删除一个进行中的任务：目录与状态被移除，活跃指针被清理，刷新与 `tenon list` 都不再显示；
      git 中出现未提交的删除且没有新提交，工作台显示未提交删除的数量。
- [ ] 在工作台归档一个停在 build 的任务：工作台列表与详情入口不再显示它，磁盘文件不变；「已归档」视图中能看到它并显示停在 build。
- [ ] 取消归档后任务回到列表，阶段与记录与归档前一致，可以继续推进。
- [ ] 用户 A 归档一个任务后，用户 B 在同一仓库的工作台仍能看到并推进它；A 的「已归档」视图中有它，B 的没有。
- [ ] 已归档任务上的转移、评审、测试执行被拒绝并提示先取消归档。
- [ ] CLI 与 UI 的删除、归档、取消归档结果一致；两条入口都有测试。
- [ ] 对 AFK 运行中或有待确认评审的任务操作时，行为符合 R7。

## Out of Scope

- 回收站、跨项目批量操作。
- 改变工作流最后一步 OpenSpec 归档的行为。

- 2026-09-15 按推荐确定（用户授权后续按推荐执行）：UI 操作保留「归档」（隐藏，与 Codex 一致）；工作流最后一步及其完成状态在界面上
  改称「完结」/「已完结」，内部字段 `archived` 与 OpenSpec archive 命令不改名。
