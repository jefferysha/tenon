## Standard installer: vercel-labs/skills (`npx skills`, MIT)

- Commands: add, list, remove, find, use, init, check / update / upgrade (same `runUpdate`); flags `-g`, `-p`, `-a <agent>`,
  `--skill`, `--copy` (default symlink), `-y`, `--all`, `--full-depth`.
- Locations: Claude Code project `.claude/skills`, global `~/.claude/skills`; Codex project `.agents/skills`, global `$CODEX_HOME`
  or `~/.codex/skills` (OpenAI docs list `~/.agents/skills` — verify).
- Lockfiles: global `~/.agents/.skill-lock.json` (source, ref, skillPath, GitHub tree hash, times); project `skills-lock.json`
  (sha256 of files). No commit pinning by default; `owner/repo#ref` locks a branch/tag; otherwise tracks default branch HEAD.
- `update` compares GitHub tree hashes and re-runs `add` for changed skills; uses `GITHUB_TOKEN`; telemetry on by default
  (`DISABLE_TELEMETRY=1`).
- Alternatives: Claude Code plugin marketplaces (namespaced `plugin:skill`), Codex `$skill-installer` / `/plugins`,
  `openspec init` / `openspec update`.

## Technical constraints for upstream installation

- Codex skill evidence trusts only skills inside the selected plugin cache, active release root or development root
  (`packages/cli/src/codexSkillTrust.ts:222-247`); upstream skills installed elsewhere would not count as evidence.
- Bundle assembly and provenance verification hash the shipped skill trees (`packages/cli/src/skillBundleAssembly.ts`,
  `internal-skill-provenance verify|sync`); a skill fetched at install time changes those contracts.
- Workflow skill ids are logical ids referenced by `templates/workflows/default.yaml`, skill gates and document producer contracts;
  upstream skills must keep resolvable ids (aliases already exist, e.g. `superpowers:`).
