# Dashboard 全面 UI 与功能评审

## Goal

完整审视 Tenon Dashboard 的每个页面、页面内交互和功能点，识别视觉臃肿、信息层级混乱、重复入口、低价值功能和失效交互，形成一份按优先级排序、可直接用于后续重设计与删减的评审结果。

用户价值：让 Dashboard 从“功能很多的控制面”收敛为围绕项目状态、下一步行动和必要配置的清晰工作台。

## Product positioning and evaluation lens

- Tenon Dashboard 是本地优先的 coding-agent 工作流控制面，不是公共文档站，也不取代 CLI 的 canonical 状态操作。
- 日常操作者的核心任务是确认项目状态、找到需要介入的 Change、理解下一步并采取必要行动；治理、诊断和安装能力服务于少数配置/故障场景。
- 评审每项能力时使用五个问题：是否直接帮助核心任务、是否有明确高频用户、是否与其他入口重复、是否应该在当前上下文出现、隐藏或移除后是否影响安全/正确性。
- “功能存在”不等于“应该出现在主界面”；只有能降低决策成本或完成必要操作的能力才默认保留在主路径。

## Confirmed facts from repository and runtime

- Dashboard 一级视图由 `packages/dashboard-app/src/App.tsx` 和 `shell/Nav.tsx` 组合为：项目、进度、自动运行（AFK）、工作台、机器、宿主计划，以及一个品牌概览入口。
- 项目页负责项目发现、搜索、状态聚焦和项目选择；选择项目后进入进度页。
- 进度页包含状态筛选、Workflow 七阶段画布、新建任务、任务详情抽屉（概览/产出/终端/记录）。
- AFK 页包含队列、健康状态、搜索、开启自动运行、新建定时任务、验证定时任务、任务详情、查看流程、接管命令和重试预览。
- 工作台包含 Workflow 选择/复制/新建、治理轨、Track 选择与设置、策略编辑、阶段编辑、Skill 编排、执行指令、未保存变更保护等大量配置交互。
- 机器页聚合 Codex 凭证、技能包、生产操作、Docker、沙箱镜像、阻断项、跨项目风险和高级诊断/流量面板。
- 宿主计划页包含 12 个宿主目标选择、安装/更新操作、命令复制、计划预览和当前项目上下文。
- 概览页是约 4,400px 的长说明页，包含模式、七阶段、证据链、模块、安装、宿主分级和安全边界等多个营销/说明区块。
- 运行时在 1200px 视口可访问所有主要视图；无水平溢出，但工作台、宿主计划、概览纵向很长。
- 进度页运行时产生 React 重复 key 警告，重复 key 为 `/Users/a1234/Documents/code-manager/projects/tenon-local::default`，来源 `WorkflowCanvas`。
- 打开进度任务详情后出现 `prg9-scrim` 遮罩；遮罩存在时侧栏点击会被拦截，必须先关闭详情。
- 当前 Vite 开发环境中，请求 `/api/orchestration/changes/dashboard-ui-reimplementation?...` 返回 404；其它主要 snapshot、machine、host-plan 请求可返回 200。该项需要区分开发代理配置问题与产品运行时问题。
- 页面运行时未发现 console error 级别以外的网络失败；`npm ls --depth=0` 和 `git diff --check` 通过。

## In scope

1. 页面级评审：项目、进度、AFK、工作台、机器、宿主计划、概览、设置浮层、离线/错误/空状态。
2. 交互级评审：导航、面包屑、筛选、搜索、标签、抽屉、对话框、表单、选择器、复制、重试、刷新、未保存保护、键盘与移动端行为。
3. 功能级评审：逐项判断功能的用户价值、使用频率假设、重复性、信息成本、失败可恢复性和是否应保留/合并/隐藏/删除。
4. 视觉与信息架构评审：密度、层级、留白、长页面、术语、状态表达、主次行动、响应式布局和可访问性线索。
5. 运行态证据：桌面/平板/移动断点、页面高度和溢出、控制数量、控制台与网络异常、关键只读交互路径。
6. 输出一个按 P0/P1/P2 排序的评审报告，并给出目标信息架构和后续改造批次建议。

## Out of scope

- 本阶段不直接修改 Dashboard 产品代码。
- 不执行会写入项目状态、创建任务、安装/更新宿主、运行 AFK 或删除数据的操作。
- 不把一次开发环境代理 404 直接判定为生产功能缺陷，除非能从代码和服务端路由进一步证实。
- 不以自动化 axe 结果替代完整的键盘、焦点和屏幕阅读器判断。

## Acceptance criteria

- [ ] 评审报告覆盖全部一级页面和每页列出的交互入口。
- [ ] 每个发现包含：页面/功能位置、问题描述、证据、影响、优先级和建议动作（保留/合并/隐藏/删除/重做）。
- [ ] 明确区分视觉问题、信息架构问题、交互缺陷、技术缺陷和产品取舍。
- [ ] 给出精简后的核心用户路径，以及建议移出主导航或删除的功能清单。
- [ ] 覆盖 375px、768px、1440px 三个断点，并记录水平溢出、纵向长度和关键响应式问题。
- [ ] 记录控制台警告、网络失败和无法验证的项目，避免把部分检查表述为全量通过。
- [ ] 产出后续重设计的阶段顺序、验收标准和需要用户拍板的取舍。

## Key decision

- 用户已确认可以对低频、重复或只服务内部治理的功能提出移出一级导航、合并或删除建议；评审以“项目 → 当前进度 → 下一步行动”为主路径，其余能力优先下沉到详情或高级设置。
