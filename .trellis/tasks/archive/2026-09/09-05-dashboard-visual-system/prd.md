# Dashboard 视觉系统与组件提升

## Goal

建立服务于本地控制面任务优先级的统一视觉语言，减少色块堆叠和视觉噪声，提升组件可读性、反馈和响应式体验。

## Scope

- 建立 primitive/semantic/component 三层 token，统一画布、表面、边框、文字、强调色、成功/警告/危险、焦点和禁用语义；支持浅色/深色主题而不在组件内写散落 hex。
- 重做页面布局节奏：内容列、任务列、详情列和 section 间距统一；减少无信息装饰色块，明确主/次表面关系。
- 统一卡片：标题/状态/元信息/动作层级，减少嵌套边框和过度阴影。
- 统一按钮：primary/secondary/ghost/danger/icon、尺寸、图标间距、hover/focus/pressed/disabled/loading。
- 提升选择框与表单控件：标签、占位、选中态、键盘操作、错误说明、禁用态和移动端触控尺寸。
- 将 Progress/Workbench 的画布变为可读的阶段列表/轻量轨道；完整 DAG 进入详情，不以固定宽度制造首屏横滚。
- 统一抽屉/对话框、空态、加载、错误、toast 和确认反馈；补齐焦点管理与 reduced-motion。
- 在 375/768/1440 视口做浏览器验收，覆盖 hover/focus/keyboard/touch 和中英文文案长度。

## Acceptance Criteria

- 核心页面只引用语义/component token，颜色、圆角、间距和阴影不再散落定义。
- 视觉层级能在 3 秒内区分当前任务、状态和主动作；辅助信息不会与主动作竞争。
- 卡片、按钮、选择框、画布、抽屉/对话框的状态和交互反馈一致，键盘焦点可见且不被裁切。
- Progress 任务列表和 Workbench 阶段编辑在移动端不需要横向滚动；触控目标满足可用尺寸。
- 空、错、加载、保存中、保存成功/失败均有明确文案和恢复路径。
- 组件测试和真实浏览器回归覆盖关键状态，typecheck、web tests、diff check 通过。

## Non-goals

不引入新的业务能力或新的设计依赖；不以纯装饰动画替代状态反馈；不在未完成 IA 收敛前大面积抛光旧布局。
