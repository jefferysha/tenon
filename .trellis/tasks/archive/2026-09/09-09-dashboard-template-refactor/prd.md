# Dashboard 基于工作空间模板的整体重构

## Source of truth

用户提供的工作空间模板截图是本任务**唯一的视觉与 IA 基准**。任何与它冲突的历史 PRD、
历史 design demo（v10b/v10c 等）、既有组件写法一律作废，不得再作为需求来源。

前置纠偏记录：09-05-dashboard-visual-system / 09-05-dashboard-ia-simplification /
09-05-dashboard-experience-rework 三个任务的口径是「在旧 IA 上做视觉抛光」，与用户真实
意图（换 IA 骨架）不符，已于本任务创建前全部归档。

## Goal

把整个 dashboard 换成模板的骨架：**顶部横条导航 + 三列工作空间阅读页**；模板未覆盖的
页面（阶段 / 自动化 / 机器）由本任务按同一设计语言重新设计，不允许沿用旧版式。

## 模板已定义的部分（1:1 复刻，不得自由发挥）

### 顶部横条
logo 方块 → 面包屑「工作空间 / 工作台」→ 项目切换器（状态点 + 项目名 + chevron）
→ 标签导航（工作台 / 阶段 / 自动化 / 机器）→ 搜索框（放大镜 + 占位 + `/` 快捷键提示）
→ 只读视图 pill → 连接状态（绿点 + 已连接）→ 头像。

### 三列工作空间页
- **左列 · 项目选择**：可折叠；项目卡 = 首字母方块 + 项目名 + 「N 个任务 · 描述」+ 右侧计数；
  选中态为浅绿底 + 绿边框 + 绿字。列底固定「所有项目」「设置」两个入口。
- **中列 · 任务列表**：eyebrow「<PROJECT> · 工作空间」→ H1「任务」→ 筛选说明框
  「需要你 = 待决定 / 受阻」→ 任务搜索框 → 状态页签（全部 / 需要你 / 进行中 / 待复核 /
  已完成，各带计数）→ 任务卡（标题 + slug + 阶段图标 + 文件数 + 「下一步 · …」+ chevron）。
  选中卡有独立底色与左侧粗边，未选中卡靠 1px 分隔线分隔。
- **右列 · 任务详情**：eyebrow「阶段 / 文件阅读」→ H1 任务标题 → slug → 状态 pill + 一句
  状态说明 → **六段阶段轨**（立项 / 调研 / 规格 / 实现 / 验证 / 交付；已完成段深绿、当前段
  橙、未开始段浅灰，当前段标签橙色加粗）→ **文件工作台**（输入 / 输出 tab + 计数、
  「N 可读 · N 缺失」、文件行卡、「查看全部 N 个文件」）→ 文件预览卡 → 底部说明与
  「打开任务详情 →」。

六段阶段对应内核 `CONTEXT_BUNDLE_PHASES`：open / explore / spec / build / verify / ship。
文件工作台对应 `contextBundlePreview` 的 trusted reader（kind / path / digest / mode）。

### 工作台右列的语义（用户 2026-09-09 纠正后固定）

工作台展示的是**一个任务在每个 stage 的具体执行状态，以及每个 stage 的产出**：
- 「阶段执行」列表逐 stage 给出状态（已完成 / 进行中 / 待决定 / 受阻 / 待开始）、
  参与的技能及其调用结果、门禁状态、本阶段登记的产出与缺失。
- 选中某 stage 后展开该阶段的技能执行波次（同波并行、波间串行）和文件工作台
  （输入 = 上游产出与依据文件；产出 = 本阶段技能登记的文件，含 已登记 / 缺失 / 过期）。
- 六段阶段轨与「阶段执行」列表是同一份数据的两种呈现，口径必须同源。

## 模板未定义、需本任务重新设计的部分

风格必须贴近模板（同一套 token、同样的留白节奏、同样的卡片与 pill 语汇），但版式自定。

- **工作流**（顶部标签由「阶段」改名）：**整个工作流的定义编辑页**，不显示任何任务状态。
  编辑对象 = 工作流、轨道、管线、阶段，以及每个阶段内技能的执行顺序（串行 / 并行）。
  阶段的输入与产出**由技能与上游阶段动态推导并只读展示**，不允许用户手填。
- **自动化**：AFK 自动运行的运行态、失败处置、节奏配置。
- **机器**：机器 / 宿主目标 / 适配器安装。

## 写操作边界

模板底部「创建、安装和执行留在终端；工作台负责阅读和定位」只约束**工作台这一页**：
三列阅读页不承载写操作，需要动作时给出对应终端命令与定位。

**例外（用户明确要求）：工作流的新增与编辑必须继续在 web 端完成完整增删改查**，
落在「工作流」页，不受只读口径约束。

## Acceptance Criteria

- 顶部横条替代左侧 88px 图标 rail；rail 及其相关测试下线，无并存的两套导航。
- 三列工作空间页在 1440 视口按模板还原：列宽比例、字号层级、状态色、阶段轨配色一致。
- 任务列表页签计数、任务卡「下一步」文案、详情阶段轨与文件工作台均接真实快照数据，
  不使用占位数据。
- 文件工作台的输入 / 输出、可读 / 缺失状态来自 contextBundlePreview，缺失文件有明确表述。
- 工作流页保留工作流 / 轨道 / 阶段 / 技能顺序的完整增删改查，且脏态导航拦截仍然有效；
  阶段输入与产出只读且由定义推导，界面上不存在手填入口。
- 工作台右列能逐 stage 看到执行状态、技能调用结果和产出登记情况，不只显示当前阶段。
- 工作流 / 自动化 / 机器三页与工作台共用同一套 token 与组件，无残留旧版式。
- 375 / 768 / 1440 三视口无横向滚动；键盘焦点可见；`/` 聚焦搜索。
- typecheck:web、test:web、check:design-scale 通过。

## Non-goals

- 不新增后端能力；文件工作台只消费既有 contextBundlePreview 契约。
- 不在本任务内做动效编排以外的性能优化。
- 不保留旧 IA 的兼容开关。
