# 整条工作流编排总览

## 背景
没有任何页面能看到整条工作流 × 每阶段的执行者/技能/测试/评审者/门禁/文档流向；单阶段画布把技能画成并行而 runner 严格串行（`cli/src/commands/statusStepParts.ts:92-101`），且 runner 先执行者后技能，页面顺序相反；工作台读当前定义而非任务冻结计划。

## 需求
- R1 顺序真相：runner 按声明的 `depends_on` 构建技能波次（同波并行、跨波串行）；未声明依赖的技能保持声明顺序串行（与现行为一致）。技能门与状态投影同一实现；画布按同一数据画。
- R2 内核编排投影：`buildOrchestration(plan, track)` → 每阶段有序条目 `{kind: executor|skill|test|reviewer, id, label, wave, dependsOn, required, source(declared|openspec|manifest)}` + 阶段门禁 + 回流边 + 文档流（生产者→消费者）。OpenSpec 注入技能在内核计算（移出前端 producers.ts 的推算）。接口 `GET /api/workflows/:name/orchestration?track=`；任务级 `GET /api/change/:c/orchestration?root=`（读冻结计划 + 运行状态）。
- R3 工作流页「总览」：左栏阶段列表顶部加「总览」行（第 0 步）；右栏变为全宽 React Flow 画布：每阶段一列（单线框分组，不堆卡片），列内按真实顺序 执行者 → 技能 → 测试 → 评审者，门禁图标在列头，回流为虚线弧，悬停显示文档流向；GSAP 脉冲从起点到终点持续传递；可缩放、适应视图、全屏。
- R4 工作台「总览」：任务详情加「总览」页签，同一画布，节点带运行状态（运行中/完成/等待/失败），当前阶段高亮；读任务冻结计划。
- R5 右栏收敛：单阶段右栏为 输入 → 技能 → 输出 → 门禁 四段；「技能」画布内用泳道同时显示执行者、技能、测试、评审者（与总览同一组件的单列形态）；「退回」并入门禁段。
- R6 性能：总览画布 7 阶段 × 30 节点首屏 < 300ms；快照不因编排数据变慢。

## 验收
- 前端轨道 explore 的 4 个技能：未声明依赖时画成串行 4 步；声明依赖后画成波次且 runner 真按波次放行。
- 总览在工作流页与工作台均可见，工作台状态与 `tenon status` 一致。
- 右栏只有四段。
