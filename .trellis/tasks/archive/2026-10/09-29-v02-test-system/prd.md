# 测试体系：每次开发登记全部测试脚本

## 目标

每个开发任务（change）都必须把它依赖和新增的**全部测试脚本**登记进来——单测、集成、回归、e2e、Playwright、浏览器测试、基准、类型检查、覆盖率、可访问性、视觉回归等——由 Tenon 真正执行、按用例解析结果、保留可查看的产物，并按工作流策略卡住阶段出口。登记在终端完成（agent 调 CLI），Dashboard 只展示与配置策略。

## 背景（v0.1.10 现状，2026-09-29 审计）

- 已有：步骤级 `tests[]`（从测试方向模板复制）、`tenon test run <change> <test-id>` 真执行（退出码、日志、产物、指标、代码指纹失效）、缺失/过期挡出口。
- 缺：结果只有「一条命令过/不过」，不解析用例；`exit 0` 也算通过；测试不是按任务登记而是写死在工作流模板；新增的测试文件没人要求登记；无服务编排；基准无阈值、基线按用户且不分机器；`scope: known` 无行为；Playwright 目录产物打不开；页面只露出一半且全是自由文本；记录可被 shell 重定向伪造。

## 需求

- R1 项目测试目录：项目内一份共享的测试套件清单（runner、命令、报告格式、覆盖率、产物、服务、基准、重试、标签、影响范围），支持自动发现。
- R2 任务测试登记：每个 change 一份测试计划，由 CLI 独占写入；列出本任务涉及的套件与本任务新增/修改的测试文件，并把 OpenSpec 场景与 tasks.md 条目映射到测试用例。
- R3 全量登记强制：diff 里新增/修改的测试文件必须全部登记；未登记即阻塞。
- R4 工作流测试策略：按轨道、按阶段声明必须登记/必须运行的测试种类、范围、覆盖率门槛、基准要求、重试与 flaky 口径；default 各轨道给出合理默认值；旧的步骤 `tests[]` 继续有效。
- R5 结构化执行：批量运行（按套件/种类/阶段/全部/变更范围），启动与回收依赖服务，解析 JUnit / Playwright JSON / Vitest JSON / Jest JSON / go test -json / pytest JUnit / TAP 与基准 JSON，得到用例级结果；0 用例、报告与退出码不一致、已登记用例未出现在报告里，一律判失败。
- R6 覆盖率：解析 istanbul summary / lcov / cobertura，按策略门槛判定。
- R7 基准：多次运行取中位数与 p95，按机器画像存基线（进 git），同画像比较退化百分比；无同画像基线时提示建立基线而不静默通过。
- R8 回归：全量回归每次在当前代码上跑；已知失败清单（带原因、链接、到期日）让「仍失败」不阻塞、「新失败」阻塞、「已修好」提示移出清单。
- R9 重试与不稳定：失败用例按套件配置重试；重试后通过记为 flaky 并计数，策略可规定 flaky 上限。
- R10 浏览器测试：Playwright 脚本是唯一可计入的浏览器证据；支持多浏览器项目、视觉快照、a11y；探索式浏览器检查必须落成脚本才计入。产物（截图、trace、视频、HTML 报告）按文件建立索引，页面可直接查看或下载。
- R11 证据与门禁：记录 v2（套件运行 + 用例 + 覆盖率 + 指标 + 服务 + 产物索引），与代码指纹、目录摘要、计划摘要、工作流指纹绑定；阻塞码覆盖计划缺失、种类缺失、未登记文件、未运行、失败、过期、0 用例、已登记用例未执行、覆盖率不足、基准退化、flaky 超限、场景未覆盖。
- R12 防伪：记录只能由 `tenon test run` 写入，按哈希链串联；hook 拦截对记录目录的写、改与 shell 重定向；链断显示「记录被改动」并视为未运行。
- R13 追溯报告：场景/任务 → 用例 → 最近结果的矩阵，自动写进验证报告。
- R14 流程接入：tenon 技能与 runner 的下一步动作覆盖 发现 → 登记计划 → 写测试并登记文件 → 按阶段运行 → 报告；评审者可读测试结果。
- R15 Dashboard：项目页「测试」（目录与基线）、工作台任务「测试」（登记矩阵、用例级失败、运行详情、产物查看、覆盖率、基准对比）、工作流页测试策略的结构化表单、库里的测试模板（按 runner）只读展示。登记不在页面进行。

## 验收

- A1 在一个新项目里：`tenon test discover` 识别 vitest / playwright / 基准脚本并生成目录；agent 按技能流程登记计划；缺任一策略要求的种类时 spec 出口被挡且原因可读。
- A2 build 阶段新增一个 `*.spec.ts` 不登记 → 出口被挡（test-file-unregistered）；登记后运行，报告里出现该文件的用例才放行。
- A3 `"test": "exit 0"` 或 0 用例 → 判失败（no-tests-ran）。
- A4 Playwright 套件：自动启动 dev server、等待就绪、跑 chromium+webkit、失败截图与 trace 在工作台可直接打开，结束后服务被回收。
- A5 基准：首次提示建立基线；同机器画像下退化超过阈值被挡；换机器只提示不挡。
- A6 回归：已知失败清单里的用例失败不挡；新失败挡；已修好的提示移出。
- A7 flaky：重试后通过的用例标记 flaky 并计数；超过策略上限被挡。
- A8 用 shell 重定向改写记录 → hook 拦截；手工改动 → 哈希链断、视为未运行。
- A9 验证报告自动含追溯矩阵；每个 OpenSpec 场景至少一个通过用例或有评审批准的豁免。
- A10 Claude Code 与 Codex 各跑通一次（记录在验收任务）。
- A11 v1 记录与旧步骤 `tests[]` 在升级后仍可读、仍生效。

## 非目标

- 不在 Dashboard 上执行测试或登记测试（Dashboard 不调模型、不跑命令）。
- 不做分布式/远程执行与测试分片调度。
- 不自建浏览器录制器；探索式检查用现有 browser-qa 技能 + Playwright codegen 落脚本。
