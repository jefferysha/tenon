# 多用户协作

## Goal

多个开发者用 Tenon 协作同一批项目时，Tenon 知道当前用户是谁，记录每个关键操作是谁做的；任务区分用户，
有创建者和负责人，工作台上一眼看出任务属于谁、能只看自己的任务；多人在同一仓库工作互不覆盖对方的个人状态。

## Background (confirmed, see `research/identity.md`)

- Trellis 的身份是本机声明的名字：环境变量 `TRELLIS_DEVELOPER` → gitignored `.trellis/.developer` → 主工作树的 `.developer`
  （`common/paths.py:100-139`），不做认证；任务 `creator` / `assignee`，`list --mine` 按名字匹配；每人一个工作区与追加式日志。
- Tenon 目前没有「谁」：评审只记渠道（terminal / dashboard / delegated），转移 `actor` 故意留空，
  编排 v2 的 actor id 写死 `cli` / `dashboard`，Dashboard 一台机器一个令牌且声明「令牌不是人的证据」。
- 同一仓库的 `.pipeline-active`、`.pipeline-interaction-authority` 是全员共用的单文件，多人会互相覆盖。
- 工作台任务列表目前按工作流 → 轨道 → 阶段筛选（`dashboard-app/src/workspace/TaskListPane.tsx:48`），没有用户维度。

## Key Decisions

- 2026-09-15 用户确认身份：默认取 `git config user.email`（显示名取 `user.name`），可在本机覆盖，
  优先级为环境变量 → 本机配置文件 → git 配置；不做登录；所有记录标注为「自报身份」。
- 2026-09-15 用户要求：测试记录在项目根目录下按用户分目录维护（见 `09-15-test-evidence`）。
- 2026-09-15 用户确认：归档只对归档的人生效，状态存在该用户自己的目录下（见 `09-15-task-delete-archive`）。
- 2026-09-15 用户要求：任务需要区分用户，并在 UI 上体现。
- 2026-09-15 用户确认：只有负责人能推进任务，其他人先「接手」再推进。

## Requirements

- R1 当前用户身份按上面的决定获取；CLI、hooks、Dashboard 使用同一身份。
- R2 记录操作人：创建任务、评审请求与确认、转移、文档登记、测试执行、agent 运行、指令文件与模板修改、任务删除、归档与取消归档。
- R3 每个任务有创建者与负责人（创建时默认为当前用户），负责人可修改且留痕。
- R3a 只有负责人能推进任务（转移、评审请求、测试执行、agent 运行、文档登记）；其他用户可查看；
  其他用户通过「接手」把负责人改为自己并留痕后才能推进。CLI 与 Dashboard 都提供接手，非负责人推进时提示先接手。
  身份为自报，该限制用于防误操作，不防故意冒名。
- R4 工作台体现用户：
  - 顶栏显示当前用户；
  - 任务卡显示负责人；
  - 任务筛选增加用户维度（我的 / 全部 / 指定用户），与工作流、轨道、阶段筛选并列；
  - 任务详情与各类记录（文档、测试、agent、评审、转移）显示操作人。
- R5 个人状态按用户隔离：当前活跃任务、交互授权、归档状态不再是全仓单文件；项目内的按用户目录结构由本子任务统一定义
  （测试记录也放在其中）；共享数据（任务、文档、评审记录）随 git 共享。
- R6 身份未设置（没有 git 邮箱也没有覆盖）时，CLI 与 Dashboard 引导设置，不静默写入匿名。

## Acceptance Criteria

- [ ] 两个用户（不同身份）在同一仓库各自创建并推进任务：个人状态互不覆盖，各自的活跃任务正确。
- [ ] 工作台顶栏显示当前用户；任务卡显示负责人；「我的」只显示负责人为当前用户的任务，「指定用户」筛选结果正确；
      修改负责人后筛选结果随之变化并留痕。
- [ ] 评审确认、转移、文档登记、测试运行、agent 运行记录都显示操作人，git 同步后对另一用户可见。
- [ ] 未设置身份时，CLI 与 Dashboard 给出设置入口，设置后记录生效。
- [ ] 用户 B 对用户 A 负责的任务执行转移、评审请求、测试执行时被拒绝并提示接手；B 接手后负责人变为 B、留有记录，B 可以推进，A 被拒绝。

## Out of Scope

- 集中式账号系统、登录、每用户令牌、单点登录、跨机器共享的 Dashboard 服务。
- 防冒名：自报身份可被修改 git 配置冒用，已接受。
- 权限模型（谁能评审谁的任务）。
