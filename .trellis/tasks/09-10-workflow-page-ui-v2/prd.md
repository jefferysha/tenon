# PRD · 工作流页 UI 重设计（v2）

## 背景

用户对 `d8a7e85` 的工作流页给出四点反馈（截图 12–16）：

1. 左栏动作全部堆在底部（新建工作流 / 新建轨道 / 导入 / 导出 / 删除轨道 / 恢复内建），
   而不是在标题旁用 `+`、在每个工作流 / 轨道行上就地操作。整体「太丑」。
2. 中栏太挤（每张卡列出全部技能芯片），右栏太空。中栏只应展示阶段名称与门禁类型，但要有设计层次。
3. 右栏空洞、技能展示业余（一列裸芯片）、区块间距过密。
4. 输入 / 输出必须用面包屑方式在右栏内切换 sheet，而不是抽屉；sheet 里的行把溯源当描述文字塞进去，
   很丑；且「添加输出」不应存在（用户认为 IO 是自动检测的）。用户要求解释 IO 识别原理。

## 目标

- 左栏：`工作流` 标题右侧一个 `+`（新建 / 导入合一，复用现有三模式对话框）。每个工作流行有行内
  `+`（新建轨道）与 `⋯`（导出 YAML；删除工作流 / 恢复内建）。每条轨道行有行内 `×`（删除轨道）。底部清单删除。
- 中栏：只有名称与门禁的流程骨架；列宽收窄（把空间让给右栏）；分支页签删除（左栏轨道行是唯一切换处）。
- 右栏：面包屑 `工作流 / 轨道 / 阶段（/ 输出|输入）`；标题即阶段名可直接编辑；技能按波次卡片化
  （来源图标 + 名称 + SKILL.md description）；`输出 / 输入` 两张摘要卡，点开在右栏内切换成 sheet，
  面包屑返回；门禁三选保留 hover 解释。
- IO sheet：只读；每行 = 槽位名 + 锁 + 产出技能芯片 + 上/下游阶段芯片；不再有添加 / 移除 / 勾选。
- 原理说明写进 spec，并把「文档槽位按阶段 id 查固定表，不看技能」这一事实作为已知限制记录。

## 非目标

- 不改 kernel IO 推导规则（technical follow-up：按技能声明推导输出，另立任务）。
- 不改技能编排浮层。
- 不改工作台页。

## 验收标准

- [ ] 左栏没有底部动作清单；`wb-workflow-new`（+）打开新建对话框；`wb-track-new-<wf>` 打开新建轨道；
      `wb-wf-menu-<wf>` 弹出菜单含导出 / 删除或恢复；`wb-track-delete-<track>` 出现在轨道行。
- [ ] 中栏卡片不含技能芯片；含名称与门禁标记；无分支页签；拖拽排序仍可用。
- [ ] 右栏面包屑 `wb-crumbs` 依次为工作流、轨道、阶段；打开输出后追加 `输出`，点阶段 crumb 返回。
- [ ] `wb-lane-name-<id>`（文本）与 `wb-lane-name-input-<id>`（可编辑）同时存在，App 测试不改。
- [ ] 技能区每个技能为卡片 `skill-card-<id>`，含来源图标与 description（registry 有则显示）。
- [ ] IO sheet 无 `output-picker` / `output-add` / `output-remove` / `input-check`；行含 `slot-skills-<id>`
      与 `slot-stages-<id>` 芯片组。
- [ ] `typecheck:web`、`test:web`、`check:design-scale`、`check:comments`、`build:web` 通过。
