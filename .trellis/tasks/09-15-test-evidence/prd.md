# 每步测试登记

## Goal

工作流每一步可以声明需要跑的测试项；测试由 Tenon 真实执行，每项测试的输入、输出和结果被登记、绑定到当前代码版本，
并参与门禁；测试记录在项目根目录下按用户维护；工作台能看到每步测了什么、用了什么输入、产出了什么、结果如何。

## Background (confirmed, see `research/current-test-evidence.md`)

- 交互流程里没有任何地方执行测试并记录退出码；测试证据只有 agent 手填的字符串、一份验证报告和技能里的文字要求。
- 结构化结果只存在于自动化循环：`VerificationResult` 的 `command-result {command_id, exit_code, stdout_sha256}`
  （`kernel/src/verification/types.ts:60-127`）。
- 文档台账不适合承载测试：固定文档类型、重登记覆盖历史、没有命令和退出码字段（`state/document-ledger.ts:53-63,358-364`）。
- 前后端差异目前只体现在技能列表（前端 verify 多 `browser-qa`、`e2e-testing`），没有强制。

## Key Decisions

- 2026-09-15 用户确认：测试由 Tenon 执行（agent 调用 Tenon 命令，Tenon 启动进程并记录真实结果）；agent 自己运行的结果
  不能满足必需测试。
- 2026-09-15 用户要求：测试记录放在项目根目录下，按用户分目录维护（与多用户子任务的用户身份一致）。
- 2026-09-15 用户要求：测试方向在 UI 上可配置；每个测试项的输入和输出也要登记。
- 基准基线跟随测试记录按用户维护：基准数值受机器影响，跨用户比较没有意义。

## Requirements

- R1 测试方向可配置：内置单测、集成、回归、基准、Playwright、e2e，用户可在 UI 新增、编辑、删除方向
  （例如接口测试、安全扫描、代码规模检查）；方向带默认命令模板、默认输入输出声明、默认通过标准。
- R2 步骤声明测试项：名称、方向、命令、工作目录、超时、必需或可选、通过标准（退出码；基准为指标阈值或相对基线的退化比例）、
  适用轨道。
- R3 测试项声明输入：上游文档（如 delta spec 的场景）、测试数据或夹具文件、环境变量与依赖服务、被测代码版本；
  运行时记录每个输入的实际值或文件摘要，结果可追溯到「用什么测的」。
- R4 测试项声明输出：报告文件（如 JUnit XML、HTML 报告）、覆盖率、指标文件、Playwright trace / 截图目录、日志；
  运行后登记每个输出的路径与摘要，声明的必需输出缺失时该次运行判定失败。
- R5 Tenon 执行命令并登记：退出码、开始 / 结束时间、耗时、输出摘要与完整日志、执行人、所在步骤访问、候选版本
  （build token 或工作区指纹）。
- R6 存储：测试记录在项目根目录下按用户分目录维护；具体目录结构、哪些内容进 git（记录摘要）与哪些只留本机
  （trace、截图、完整日志等大文件）在 design 中确定。
- R7 结果绑定候选版本：代码变化后旧结果显示为过期，不能用于放行。
- R8 必需测试未通过、过期或必需输出缺失时，转移、`tenon check`、评审请求被拦截，提示哪项测试和原因。
- R9 回归：可声明为全量测试集或已知问题回归集；基准：记录数值并与该用户的基线比较，基线更新留痕。
- R10 前端默认模板声明类型检查、单测、Playwright/e2e；后端默认模板声明单测、集成测试；由工作流模板或项目配置决定，
  不写死在代码里。
- R11 Dashboard：工作流页配置测试方向与每步测试项（含输入输出声明）；工作台每步「测试」页签显示每项状态、耗时、
  最近执行时间、执行人，可打开输入、输出、日志、trace、截图。
- R12 验证报告的测试部分由登记结果生成，不再手写。
- R13 大文件默认每项测试在每个任务中保留最近 5 次运行，更早的只保留结果摘要；保留次数可配置。

## Acceptance Criteria

- [ ] 在 Dashboard 新增一个测试方向（带默认命令和输入输出声明），并在自定义工作流的 build 步骤声明单测、verify 步骤声明
      回归 + Playwright + 基准 + 新方向测试项；保存后 YAML 与重新打开的界面一致。
- [ ] 在 Claude Code 和 Codex 真实任务中通过 Tenon 执行测试：工作台显示真实退出码、耗时、执行人、输入摘要、输出文件；
      agent 自报「通过」无法满足必需测试。
- [ ] 测试记录出现在项目根目录下当前用户的目录中；另一个用户在同一仓库执行后，记录分别位于各自目录且互不覆盖。
- [ ] 必需测试失败或必需输出缺失时转移被拦截；修改代码后之前通过的结果显示为过期并再次拦截，重跑通过后放行。
- [ ] Playwright 失败时可以在工作台打开 trace 或截图。
- [ ] 基准结果超过阈值时判定失败，并显示与该用户基线的差异。
- [ ] 验证报告中的测试部分由登记结果生成。

## Out of Scope

- 托管 CI 或远程测试执行集群。
- 覆盖率平台集成（可作为后续）。
- 跨用户、跨机器的基准比较。
