# 架构决策记录：测试设置简化

> 说明：本文为满足本任务冻结的文档契约而写（该契约要求调研步登记一份由 brainstorming 产出的 ADR）。本文只列决定，细节以设计文档 `docs/superpowers/specs/simplify-test-settings-design.md` 为准，不重复其内容。

## 背景

测试设置都能在文件里改，但太繁琐：

- 每步策略十几个键，测试种类有 17 个；
- 改过的测试文件要逐个登记；
- `--auto` 放宽 glob、误收归档里的非测试文件；
- 改目录会丢注释；
- 场景映射满屏「未覆盖」；
- 信任按检出各存一份；
- `code-size` 固定 2000 行上限；
- 运行记录带绝对路径；
- 未声明的测试输出让候选失效。

详见设计文档「背景」。

## 决策

1. 每步只写 `test: none | plan | changed | full`。旧 `test_policy` 只做兼容读取，两者在同一步互斥。——设计文档 §1
2. 档位含义与阈值写在 `.tenon/tests/catalog.yaml` 的 `levels`，有内建缺省。每档只有 `required`、`touched`、`scenarios`、`coverage`、`flaky`、`require_baseline` 六个键。套件按 `files` 或 `covers` 判断是否被改动碰到；没写 `covers` 的套件因此没跑、而本任务改了源码时，给出不阻断的提示 `suites-without-covers`。——§2
3. 测试种类按五类（unit、integration、e2e、static、benchmark）加 custom 归组。档位与界面只用类名，旧种类名保留为别名，旧策略仍按种类逐字匹配。——§3
4. default 选档：轻量为 实现 changed / 验证 full；产品为 规格 none / 验证 changed；前端、后端为 规格 plan / 实现 changed / 验证 full。——§4
5. 改动过的测试文件按套件 glob 在求值时自动认领，不写进计划。改动口径排除控制目录，测试文件名要求源码扩展名。`--auto` 只追加精确路径。——§5
6. 目录写回按节点替换文本区间，保留注释。——§6
7. 场景映射默认不要求，追溯矩阵不要求时收起。——§7
8. `code-size` 默认不设上限，需要时按需在 YAML 写回。豁免展示附带最新实测值。——§8
9. 测试信任存进用户级状态目录：
   - 键为「用户 + 仓库（git common dir，经 worktree 列表反查）+ 单条命令摘要」，同一仓库的 worktree 共享；
   - 仍只能由用户本人确认；
   - 只在确定不是 git 仓库时认检出旧封存；git 仓库里一律不认（检出里的封存与密钥可能随压缩包带来），旧信任要重新确认一次。——§9
10. 运行记录里的仓库与主目录绝对路径改写为相对路径与 `~`。——§10
11. 测试输出目录下未跟踪、证据扩展名的文件不计入候选指纹。以下照旧计入：已跟踪的文件、源码扩展名的文件、能被代码或浏览器直接加载的格式（json、html、zip、har 等）。——§11

## 备选方案

见设计文档「备选方案」，以下方案均已否决：

- 档位写死在代码里；
- 档位定义放工作流 YAML；
- 把认领写进计划；
- 种类改名迁移；
- 信任跨仓库共享；
- 信任存进 `.git/`；
- 按 gitignore 排除整个输出目录；
- 只调高 code-size 上限。

## 后果

- 工作流步骤新增 `test` 键，目录新增 `levels` 键与种类 `static`；`next` 的测试动作减少；信任存储位置变化。`docs/CONTRACT.md`、用法文档与发布说明需同步。
- N-1 版本读不了新键，回滚前要先结束用新键建的任务。
- 指纹规则变化会让工作区里有未声明测试输出的在途任务，在升级后一次性 `revision-stale`。
- 信任在同一路径换成另一个仓库后会被继承，与拉取新提交同属一个信任级别，列为剩余风险。
