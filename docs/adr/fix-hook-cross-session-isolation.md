# 架构决策记录：hook 按宿主会话判定「当前任务」；交互标记带归属；放行语整条匹配；评审回执可撤销

## 背景

hook 用按用户共享的 `active-change` 指针判断当前任务。同一用户在同一项目里并行多个会话时，2026-10-07 实测出现：

- 一个会话的评审标记拦住另一个会话。
- 放行语替别的任务写评审回执。
- 交互标记全项目互锁。
- 技能顺序门查错任务，技能证据记进别的任务。
- 粘贴文字里的「确认继续」被当成确认，一次规格评审因此被误记为通过，且无法撤销。

每个会话本已有精确的 `.pipeline/terminal-sessions/<session_id>.json` 绑定，hook 只是没有使用。

## 决策

1. 新增唯一的「本会话任务」解析 `pipeline_session_change_dir`，规则如下。所有拦截与记证据的 hook 都改用它；恢复候选（router / breadcrumb）不变。
   - 有本会话绑定，用绑定的任务。
   - 没有本会话绑定、而指针指向的任务已绑到别的会话，判为无。
   - 宿主不给会话 id，或该任务无人绑定，回退共享指针。
2. `.pipeline-pending-interaction` 升级为 v2，写入 change 与 session，只拦、只解归属会话；旧格式见到即删除。宿主给了会话 id 时按会话分文件 `.pipeline-pending-interaction.<会话>`，避免并行等待时后写覆盖先写（验证评审后加入）。
3. 放行语只认整条短回复，对话回复与 AskUserQuestion 答案同一规则。
4. 新增 `tenon review revoke <change> --reason <原因>`：把当前步已批准、未被消费的回执撤回为同一 event 的「待确认」并重写评审标记，写审计事件。agent 可执行。
5. 一个 Change 只绑一个会话：`session activate --host-session` 自动移交，删除其他会话对同一 Change 的绑定，并提示旧会话 id。
6. 已污染的状态在本任务里处理：
   - 串入他人任务历史的证据，追加更正事件，不删原行。
   - 误记的规格批准，等撤销命令上线后撤回为「待确认」。
   - 画布任务缺的技能证据，恢复后重新加载补齐。
7. agent 不能自己执行手动评审确认（验证评审后加入）：gate 任何时候都拒绝 agent 的 shell 调用执行不带 `--delegated` 的 `tenon review acknowledge`；确认只经放行语（hook 写入）、Dashboard、或没有该 hook 的宿主由用户本人在终端运行。第三、四轮验证评审后，判定移到 `hooks/lib/ack-command.sh`，先还原引号、转义编码与花括号再判定。
8. 验证轮次有上限（第四轮验证后用户提出）：工作流步骤声明 `max_rounds`（`default` 的 verify 为 2，未声明按 2），任务可 `tenon set … max_rounds` 覆盖；轮次按进入次数计，回规格清零；用完后不再自动回退，由用户在前进边评审门接受剩余阻断（绑定候选与评审者运行，委托确认不能接受），或调高上限、回规格、终止。

## 备选方案

- 只点修评审门、确认、交互标记与放行语：会留下证据串单。否决。
- 把共享指针改为按会话存：改动面过大，牵动恢复语义与 Dashboard。否决。
- 放行语剔除引用 / 粘贴后子串匹配：依赖宿主的粘贴标记，易漏。否决。
- 旧格式交互标记兼容 30 分钟：过渡期仍互锁。否决。
- 撤销只许用户在终端执行：撤销只会让状态更保守，不必额外设限。否决。
- 撤销后回到「无回执」：重新请求前门是开着的。否决。
- 同一 Change 允许多会话绑定、或移交需 `--takeover`：前者违背一对一要求，后者卡住会话恢复。否决。
- 删除串单的历史行：篡改审计记录。否决。
- 交互标记保持单文件、把后写覆盖写成已知限制：本任务就是做会话隔离，留下并行等待时的失效不合适。否决。
- 手动确认只在评审标记存在时拦：标记 30 分钟过期后 agent 又能自批。否决。
- 让 CLI 在终端通道要求「人在场」令牌：同机同用户下 agent 也能读到令牌，收益不抵复杂度。否决。
- 验证上限只放任务级字段、不进工作流定义：改动小，但用户要求在工作流里声明。否决。
- 上限用完后只停下、不提供接受剩余阻断：任务只能调高上限继续修，没有出口。否决。
- 恢复已删除的 review attempt 事务：按候选与车道计数，复杂且已被步骤 agents 取代。否决。

## 后果

- 并行会话之间不再互锁、不再越权确认、证据不再串单。
- 会话恢复后（会话 id 改变）在重新 activate 之前，本会话的拦截暂时不生效。离开评审步仍需 canonical 回执，门不会失守。
- 稍长的确认说法不再放行，用户需要回整条短回复。
- 新增一个 CLI 子命令和一种标记格式。
- 两个仍活着的会话先后 activate 同一 Change 时，先绑的那个失去门约束，只有 stderr 一行提示。
- 改完需要重装本地运行时才生效；已污染的历史状态需要人工撤销或补齐。
- 没有写回执 hook 的宿主（多数适配器），评审确认要由用户本人在终端运行；agent 不能代劳。
- 手动确认的拒绝是对命令文本的静态判定，变量拼出的命令名、脚本文件里的调用不在覆盖内。
- build ⇄ verify 最多默认两轮，之后由用户决定；agent 技术上能自行调高上限，只靠技能约束与同机同用户信任模型。
