# 架构决策记录：文档产出改为运行时观察，只交接直接上游

> 说明：本任务运行在升级前冻结的工作流快照上，该快照的文档契约要求调研步登记一份由 brainstorming 产出的 ADR。brainstorming 不写 ADR（ADR 属于 domain-modeling），这条契约正是本任务要删除的错误契约。本文只列决定，细节以设计文档 `docs/superpowers/specs/rework-document-mechanism-design.md` 为准。

## 背景

工作流预先规定每一步产出哪些文档、由哪个技能产出、下一步读哪些文档，与第三方技能的实际行为脱节（例如 adr←brainstorming），读取义务逐步累积，且绑死 OpenSpec。详见设计文档「背景」。

## 决策

1. 不再预定义每一步的输入、输出文档：删除工作流 YAML 的 `document_contract`，以及步骤的 `inputs` / `outputs` / `artifacts`；新定义里出现这些键时报错并给出替代写法。——设计文档 §7、§8
2. 步骤产出在运行时观察：进入步骤记 git 检查点，离开步骤（转换的锁内、提交之前）比较得到新增、修改、删除的文件；hook 只提供技能加载时间，来源按修改时间尽力标注，对不上记「未知」。——§2–§4
3. 只把直接上游那次步骤访问产出的文档交给下一步，必须全部读完（精确摘要的读取回执）才能离开这一步，终止任务除外。——§5
4. 门禁只保留按路径的必须产出（`required-output` 守卫）。——§6
5. 文档机制不认识任何规范：`spec: openspec` 只表示走 OpenSpec 生命周期；Spec Kit 等自定义规范用必须产出路径表达。——§9、§14
6. 冻结快照带文档契约的在途任务按旧账本走完；新旧只按快照有无契约分流。——§9
7. 复用 AFK 产出谱系的模型，不直接复用其运行时。——§13

## 备选方案

技能声明产出、在 Skill 的 PostToolUse 或写文件 hook 里登记、全量遍历哈希检查点、把代码也交给下一步、下一步读取全部累计产出、保留 `document_contract` 作为可选功能、只观察 `docs/` 与 `openspec/`——均已否决，理由见设计文档「方案比较」与「备选方案」。

## 后果

- 工作流 YAML 删除四个键并新增守卫类型；`status --json` 的 `step.documents` 在新任务里换成输入、产出、必须产出视图；新任务不再下发骨架、登记与字段登记动作；`docs/CONTRACT.md` 与发布说明需同步。
- 每次转换多一次 git 比较；同一检出里并行的会话会污染观察，推荐 worktree。
- 来源标注只是尽力而为，同一秒内的先后无法区分。
